## 3. 规矩

和 `docs/road-to-1.0.md` 第 2 节相同，今晚有三处不同：

- 设计写在本文，不等同意。每包一条分支，一层叠一层，不喜欢可以从那一层往后整段丢掉。
- 不开 PR、不推送、不合并。
- 该你定的事，有现状就保持现状；必须选的，选能回退的，记到第 1 节。

不做的事：花钱（不跑真 Key）、W11、删任何分支和隔离文件夹、动真实应用数据。

每包的流程：

1. 先写测试，看它因为功能缺失而失败。
2. 实现。不写防御性代码。N1、N2 只修能复现的问题。
3. 类型检查、单元测试、相关验收场景，中英文都跑。
4. 涉及画面的，截图打开看过才算。
5. 让一个没看过设计的复核代理读这一包的改动，确认过的问题修掉。
6. 更新本文和 `CHANGELOG.md`，提交。

Lewis 11 月 5 日中午改了规则：不要每次都跑全量验收，太慢，也没必要费额度。现在每包只跑和改动相关的场景加单元测试。全量验收等他开口再跑。

某一包做不下去时，写明卡在哪，跳到下一包，不硬撑。

## 4. 工作包

### N1 长跑：一百单不漏

人工验不了连开几天的店。用替身连跑一百单，中途开关卡片、切后院，每十单记一次内存、画面里的对象数、DOM 节点数和数据文件大小。

**完成标准：** 新增 `tools/sim/soak.mjs`。前后半程对比，对象数和 DOM 节点数不再增长，堆内存不持续上涨。查出来的泄漏修掉并补测试。数字写进本文。

### N2 中断和恢复

用户的电脑会断电、会杀进程。验这些情况：委托进行到一半杀掉应用再打开；写数据时杀进程；工作文件夹在委托中途被删；替身崩溃。

**完成标准：** 每种情况都有验收场景。不丢已交付的作品，能重新开张。只修复现出来的问题。

### N3 只用键盘也能开店

从欢迎页到下单、看进度、拿结果、翻书架、看后院，全程不碰鼠标。量焦点顺序、焦点能不能看见、文字和底色的对比度，三种窗口尺寸都走一遍。

**完成标准：** 新增验收场景 `keyboard`，走完一单。对比度测试覆盖主要卡片。卡住的地方都修掉。

### N4 窗外走过的人

遵守 W8 的原则：不加纯随机事件，只和真实工作有关。小橘出门跑腿和回来、街坊上门时，他们的身影先从窗外走过，从前门方向进出。玻璃会随天色变，身影也跟着变。

**完成标准：** 身影只在玻璃范围内出现，顺序和前门进出对得上。减少动画打开时不走动。中英文和两个场景都看过截图。

### N5 后院跟着店一起长

后院现在不随做过的委托变化。菜地和花坛按交付的作品数分几个阶段长起来，收成会出现在店里的果盘上。数据只读本机记录。

**完成标准：** 用模拟的 1、10、30 单历史各截一张后院，确实不同。“再改改”不算数，和 W8 一致。

### N6 店的日子

记事本里本来就有“店里的日子”，只列添过的东西。把它做成按时间列这家店的事：第几单做了什么、哪位街坊第一次来、店里添了什么、菜地怎么样。只读本机记录，不上传。

**完成标准：** 用模拟的 30 单历史看到内容正确。空店也说得通。中英文都过台词检查。长名字不撑破卡片。

### N8 打包冒烟

开发版的验收看不到打包版。图片有没有进 `app.asar`，保险丝是不是真的设了，这些只能在打包后的程序上看。

**完成标准：** 打包版接模拟 Claude 做完一单，所有图片、字体和音乐都读得到。保险丝读回来是对的，重启后作品还在，真实数据文件夹一个字节都没变。这不是 W11。

### N9 书架能找东西

作品不再丢以后，书架可能有上千件。加搜索和按种类筛选，按月分组，只用键盘也能用。记事本的委托列表只先显示最近的。用 1000 件做压力测试，量启动、开书架、开记事本的时间和 `memory.json` 的大小。顺手让 `noticeGrowth` 那句话也等说话的人有空。

**完成标准：** 1000 件时书架和记事本都在一秒内打开，搜得到、筛得出，没有结果时有话说。中英文都过。

### N10 每月账本

`spend.json` 按月有数，但只能看到本月合计。做一页只读的按月账本，写明是估算，不是 Anthropic 的账单。同时查 `MAX_ENTRIES = 500` 会不会悄悄丢掉月度数字。

**完成标准：** 模拟 14 个月的数据，每月数字和总和都对。超过 500 条时老月份的合计不变。

### N11 对比度

N3 留下来的。纸是图片，文字有的半透明，看样式表算不准。写一个工具，把每种文字遮掉再拍照，读出背后真实的颜色，算对比度。

**完成标准：** 所有主要卡片的文字到 WCAG AA：普通文字 4.5:1，大字 3:1。中英文都测。颜色改完要看图。

### N12 屏幕和缩放

这一包是今晚中途加的。开发机没开系统缩放，所以验收一直照不到大多数 Windows 笔记本的样子。用 Windows 真实的 125%、150%、175% 缩放启动，在截图上数游戏像素。再把所有主要卡片放进最小窗口量一遍。

**完成标准：** 每个游戏像素都是整数个真实像素，鼠标点得准，卡片都不跑出窗口。

### N13 坏数据不再冲掉作品

这一包也是中途加的。`memory.json` 读不出来时，店把它当空本子，下一单保存就把原文件盖掉。硬盘出错、网盘同步或手动改坏都可能碰上，结果是所有作品记录都没了。

**完成标准：** 读不出来的文件不会被覆盖。有上次的抄本就恢复。店主动告诉用户。“全部忘掉”把抄本和坏文件也一起删掉。

### N2

新场景 `crash`，中英文都过。验了这些情况：

- 委托做到一半杀掉应用：替身随之停下，重开后问要不要接着做，接着做能做完，作品只算一件。
- 结果卡开着时杀掉应用：作品还在，不再问要不要接着做。
- 留下写了一半的 `.tmp` 文件：不影响开店，数据都在。四个数据文件本来就是先写临时文件再改名。
- 委托进行中清空文件夹：店里照常收尾。Windows 不让删正在用的文件夹，所以只验了清空。
- 店关着时删掉文件夹再接着做：能结束，不会卡住。

修了两个真问题：

1. **Claude Code 中途崩溃时店里什么也不说。** 黑板还写着“还有 4 件”，人走开了回来根本不知道。现在阿灯会弹卡片，可以接着做。关掉卡片时，黑板上的计划一起清掉。
2. **接着做之后记事本里有两条。** 一条失败、一条完成，其实是同一单。现在同一个文件夹只留一条。

没查到：

- 真实 Claude Code 在应用被杀后会不会自己停。替身读到输入结束就退出，真实程序要花钱才能验，已经加进下面的“W11 要验的事”。
- 文件夹被清空后，替身不会去读旧文件，所以店里显示做好了。真实 Claude 遇到这种情况会怎样，同样要真跑。
