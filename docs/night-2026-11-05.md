## 4. 工作包

### N1 长跑：一百单不漏

人工验不了连开几天的店。用替身连跑一百单，中途开关卡片、切后院，每十单记一次内存、画面里的对象数、DOM 节点数和数据文件大小。

**完成标准：** 新增 `tools/sim/soak.mjs`。前后半程对比，对象数和 DOM 节点数不再增长，堆内存不持续上涨。查出来的泄漏修掉并补测试。数字写进本文。

### N2 中断和恢复

用户的电脑会断电、会杀进程。验这些情况：委托进行到一半杀掉应用再打开；写数据时杀进程；工作文件夹在委托中途被删；替身崩溃。

**完成标准：** 每种情况都有验收场景。不丢已交付的作品，能重新开张。只修复现出来的问题。

### N3 只用键盘也能开店

从欢迎页到下单、看进度、拿结果、翻书架、看后院，全程不碰鼠标。量焦点顺序、焦点能不能看见、文字和底色的对比度，三种窗口尺寸都走一遍。

**完成标准：** 新增验收场景 `keyboard`，走完一单。对比度测试覆盖主要卡片。卡住的地方都修掉。

### N4 窗外走过的人

遵守 W8 的原则：不加纯随机事件，只和真实工作有关。小橘出门跑腿和回来、街坊上门时，他们的身影先从窗外走过，从前门方向进出。玻璃会随天色变，身影也跟着变。

**完成标准：** 身影只在玻璃范围内出现，顺序和前门进出对得上。减少动画打开时不走动。中英文和两个场景都看过截图。

### N5 后院跟着店一起长

后院现在不随做过的委托变化。菜地和花坛按交付的作品数分几个阶段长起来，收成会出现在店里的果盘上。数据只读本机记录。

**完成标准：** 用模拟的 1、10、30 单历史各截一张后院，确实不同。“再改改”不算数，和 W8 一致。

### N6 店的日子

记事本里本来就有“店里的日子”，只列添过的东西。把它做成按时间列这家店的事：第几单做了什么、哪位街坊第一次来、店里添了什么、菜地怎么样。只读本机记录，不上传。

**完成标准：** 用模拟的 30 单历史看到内容正确。空店也说得通。中英文都过台词检查。长名字不撑破卡片。

### N7 收尾

新东西都进画面后，重拍商店图和宣传片，更新说明文档，全量验收。再让一个复核代理通读今晚全部改动。

**完成标准：** 全量验收通过，第 1 节写清查过什么、没查到什么。

### N2

新场景 `crash`，中英文都过。验了这些情况：

- 委托做到一半杀掉应用：替身随之停下，重开后问要不要接着做，接着做能做完，作品只算一件。
- 结果卡开着时杀掉应用：作品还在，不再问要不要接着做。
- 留下写了一半的 `.tmp` 文件：不影响开店，数据都在。四个数据文件本来就是先写临时文件再改名。
- 委托进行中清空文件夹：店里照常收尾。Windows 不让删正在用的文件夹，所以只验了清空。
- 店关着时删掉文件夹再接着做：能结束，不会卡住。

修了两个真问题：

1. **Claude Code 中途崩溃时店里什么也不说。** 黑板还写着“还有 4 件”，人走开了回来根本不知道。现在阿灯会弹卡片，可以接着做。关掉卡片时，黑板上的计划一起清掉。
2. **接着做之后记事本里有两条。** 一条失败、一条完成，其实是同一单。现在同一个文件夹只留一条。

没查到：

- 真实 Claude Code 在应用被杀后会不会自己停。替身读到输入结束就退出，真实程序要花钱才能验，已经加进下面的“W11 要验的事”。
- 文件夹被清空后，替身不会去读旧文件，所以店里显示做好了。真实 Claude 遇到这种情况会怎样，同样要真跑。

### N3

新场景 `keyboard`，中英文都过：从欢迎页一路到下单、看进度、拿结果、翻书架和记事本、去后院再回来、进设置，全程不碰鼠标。每按一次 Tab 都检查焦点在不在屏幕上、有没有焦点框。

查出来的问题只有一类：**所有卡片开着时，Tab 都会跑到卡片后面的店里去。** 现在焦点在卡片里循环。

没查到：读屏软件实际读出来是什么。对比度也还没量，放到 N7。

### N4

街坊上门、小橘跑腿时，先从窗外走过，再从前门进出。方向和街景小窗对得上：从屋里看，往面包店走是向左。场景 `passers` 中英文、两个场景都过。白天、黄昏、夜里的截图放大看过。

替你定的：夜里身影用浅色，当作被街灯照亮。深色在夜里的玻璃上几乎看不见。

没查到：窗帘遮掉了大半块玻璃，身影只露出一小段。效果偏含蓄，你看了可能想要更明显。
### N5

菜地开始是空的。每做完 3 单冒一棵芽，再过 3 单长熟，第 25 单时全部长满。指针放上去能看到“菜地：熟了 3 棵，刚发芽 1 棵”，键盘也能走到。场景 `beds` 用 0、1、4、12、25、60 单的历史各拍一张，截图看过，确实不同。

店员只提三次：第一棵芽、第一棵熟、全部长满。这种话一辈子只说一次，所以说话的人不在或正忙时会等，不会丢。

替你定的：

- 老用户升级后，菜地按已有单数直接长好，不用从头等。
- 计划里写的“收成出现在店里的果盘上”没做。果盘本来就在第 5 单出现，再接一层意义不大。

顺手发现：现有的成长台词（`noticeGrowth`）遇到说话的人在忙就直接丢掉，也不补。这是之前就有的行为，今晚没动，记在这里。

### N6

读代码时发现两个比计划更要紧的事：

1. **第 21 单之后，最早的作品会从书架和记事本上消失。** 店只记最近 20 单，文件还在，但在店里找不到了。一百单的长跑也测不出来，因为它不数书架。现在全部保留。喂给 Claude 的备注仍然只取最近 20 单，所以历史再长，每单也不多花钱。
2. **记事本一打开就滚过了“店的日子”。** 焦点落到了下面第一个链接上。截图时才看出来。

“店的日子”现在按时间写：第一单和第 10、25、50 单的名字、添过的东西、每位街坊第一次来的日子、菜地的三件事。场景 `days` 用 30 单的历史走一遍，书架上 30 件都在。

替你定的：作品记录不再封顶。这会改变一条之前写死的规则（测试叫“只留最近的”），不喜欢可以改回去。

老用户的记录：之前已经丢掉的作品找不回来。总单数是对的，所以“第 25 单”还数得准，但已丢的那几单不会出现在“店的日子”里。
### 复核查出来的问题（N4、N5）

第二轮复核又查出四个，都修了：

1. **菜地那句话每次启动都说一遍。** 店刚打开时，上一次的单数还是 0，所以 0 到 12 被算成了新消息。我的单元测试只走相邻两单，测不到。现在只有真的交付一单才算。
2. **下单后，正走在窗外的邻居还是会进门。** 这时邻居还不算在店里，叫走的那段代码直接跳过了。
3. **我的 `passers` 场景绕过了真实路径。** 它直接改内部变量，所以问题 2 还能通过。现在走真实的叫走函数，并且先看它失败再修。
4. **一辈子只说一次的话可能没人听见。** 现在窗口在后台或有决定卡盖着时，这句话会等一等。

还有个进程问题：我第一次写崩溃场景时只杀到了外壳，留下 2 个 Electron 进程树跑了 87 分钟。清掉了，现在的写法直接杀真正的主进程。

### 复核查出来的问题（N2、N3）

让一个没看过设计的代理读了这两包的改动，查出四个问题。我核对后都修了，每个都先补了测试：

1. 我加的 Tab 逻辑有毛病：结果卡的摘要很长、能滚动时，Tab 在摘要和 × 之间打转，后面的按钮够不着。复核代理在同版本 Electron 上实测过，我的 `keyboard` 场景原来没覆盖。现在让浏览器自己移动焦点，只有离开卡片时才拉回来。
2. 法律文本盖在设置上时，Tab 会跑到后面的设置。
3. 接着做之后，停下之前回答过的选择丢了。现在合并保留。
4. 别的卡片顶掉停止卡，或者你叫停了委托，黑板上的旧计划都不消失。现在顶掉也算关闭，叫停时直接清掉。
