# 1.5 的 E0：服务器和隐私的方案

基线：`release-1.4` 的 `cdf90db`（2026-11-21）。文中的 `路径:行号` 都对应这个提交。

这份只出方案，由 Lewis 定，对应 `docs/road-to-1.5.md` 第 7 节的 E0 和 Q-E1 到 Q-E3。三个问题答了以后，再照 `docs/road-to-1.4.md` 的样子写 1.5 的工作清单。1.4 还在发布关卡，按路线图第 2 节第 3 条，这时只出设计，不写代码。

## 1. 小灯屋现在往外连的地方

- Anthropic 的接口。委托经 Claude Code 发过去，存 Key 时先拿它试一次（`app/main/api-key.ts:106`）。
- 用户连了日历时，按用户给的订阅地址取日程（`app/main/index.ts:372`）。
- 安装版检查新版本，看的是 GitHub 上的发布页（`app/main/updates.ts`）。商店版不查，由商店更新。

商店说明里写着“没有我们的服务器”，设置、Key 和作品都只在这台电脑上（`store/listing.md:43`、`:96`）。1.5 要不要改的就是这一句。

## 2. 每一项到底要不要服务器

| 包 | 不用服务器能做到的 | 只有服务器才做得到的 |
|---|---|---|
| E2 分享作品 | 导出一份自带一切的文件：网页还是网页，文档转 PDF，图片照旧。用户自己用微信、邮件或网盘发出去 | 一个链接，朋友点开就看，随时能撤回 |
| E3 串门 | 导出一张“小店明信片”文件，里面只有摆设、长出来的东西、街上的样子和讲到第几章。朋友在自己的小灯屋里打开，能进去逛一圈 | 加了好友，随时去看对方最新的样子 |
| E4 手机端 | 桌面上的小灯屋在家里的网络里开一个小网页。手机扫码配对，在同一个 Wi-Fi 下看进度、批准请求 | 出门在外也能看，锁屏时也能收到通知 |
| E5 小团队 | 同一个网络里，几台电脑连到一间店，一台当店，其他的连过来 | 不在一个网络的人共用一间店 |
| E6 举报下架 | 发出去的是文件，没有可以下架的东西。商店政策里管用户发布内容的条款还要对一遍 | 托管的内容要有举报、审核和下架 |
| E7 运维 | 没有服务器，就没有费用、监控和备份 | 每月的费用、监控、备份、出事时的应对 |

## 3. 三个方案

**A：1.5 不做服务器。** 分享用文件，串门用明信片，手机和小团队都只在同一个网络里。

- 好处：隐私的承诺不用改，只加一句“打开手机连接以后，家里网络里配对过的手机能看到你的店”。没有月费，没有运维，没有账户，也不用找回密码。
- 坏处：发出去的文件撤不回。手机出了门就用不了。朋友要串门，自己也得装小灯屋，看分享的作品倒不用。

**B：自己托管一台服务器。** 有账户，分享是链接，串门随时能去，手机在外面也能用。

- 能用端到端加密的地方都用上。作品在本机加密，钥匙放在链接 `#` 后面那一段。服务器只存加密过的内容，自己也打不开。
- 坏处：每月有费用，要有人管监控和备份。账户要能找回，托管的内容要能举报和下架。隐私政策要重写，最好找懂的人看一遍。商店审核会按有用户发布内容的应用来看。Lewis 要对存在服务器上的东西负责。

**C：借用户自己的网盘。** 分享时把文件放进用户连好的网盘文件夹，1.3 的 C5 已经有这种连接。链接用网盘自己的分享功能，撤回就是在网盘里取消分享。手机和小团队照 A 做。

- 好处：能撤回，还是没有我们的服务器。
- 坏处：各家网盘的分享不一样，小灯屋拿不到链接，只能提醒用户自己去网盘里点“分享”。

## 4. 建议

| 编号 | 问题 | 建议 | 理由 |
|---|---|---|---|
| Q-E1 | 做不做服务器，做的话谁托管 | 1.5 不做，照 A 做。分享时多给一个选项，照 C 存进网盘文件夹 | 小灯屋一直讲的是东西都在你的电脑上，A 把这句话原样留住。B 带来的费用、运维、举报和法律责任，对一个人维护的应用太重。A 做完，看用户真正卡在哪，再决定要不要服务器 |
| Q-E2 | 手机端用网页应用还是原生应用 | 网页，由桌面上的小灯屋在家里的网络里提供 | 不上应用商店，不用 Apple 的账户，iPhone 和安卓一样用。原生应用要两套代码，还离不开推送服务器 |
| Q-E3 | 收不收费，怎么收 | 1.5 不收 | A 没有每月的成本，收费的理由不够。真做了服务器再谈 |

## 5. 照 A 做时，1.5 的包怎么变

- E1 不做账户，改成“家里网络里的连接”：配对、加密、谁能连、能做什么。后面几个包都站在它上面。
- E2 导出分享文件，可以选存进网盘文件夹。
- E3 小店明信片，导出和打开。
- E4 手机网页：看进度，批准或拒绝授权请求。网页的通知只在页面开着时有。
- E5 同一个网络里共用一间店。先做两种人：能批准的和只能看的。花费按人记。
- E6 列清楚分享文件和明信片里带什么、不带什么，再对一遍商店政策。没有托管的内容，就不用举报流程。
- E7 只剩一条：家里网络里那个小网页的安全审查。
- E8 照旧，在真实网络上用两台电脑和一部手机实测。

## 6. 照 A 做，安全上要先想好的

- 手机连接默认关，用户在设置里打开才开。只听家里网络的地址，不对外网。Windows 防火墙第一次会弹窗问，说明里要先讲。
- 配对：桌面上显示一个二维码，里面是一次性的码。之后只认配对过的手机，桌面上随时能取消。
- 手机能看进度，能批准或拒绝授权请求。不能递新委托，看不到 Key，也看不到文件夹的路径。
- 传输怎么加密要在 E1 定。家里网络里用 HTTPS 只能是自签的证书，手机浏览器会拦。一个办法是用配对码在两边各自算出同一把钥匙，网页里用浏览器自带的加密把每条消息加密后再发。
- 明信片和分享文件只带用户选的东西，不带 Key、文件夹路径和连接。打开别人的明信片时，只把它当数据读：只认已知的摆设名字和数字，不跑里面的任何东西，坏了就说打不开。
