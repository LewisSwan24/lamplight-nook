# 小灯屋 1.5 和别人一起

基线：`release-1.4` 的 `a9ce849`（2026-11-21）。文中的 `路径:行号` 都对应这个提交，代码改动后行号会漂移。

这份是 1.5 的工作清单，展开的是 `docs/road-to-1.5.md` 第 7 节。那个文件名已经是五个版本的总路线图，所以 1.5 的清单另起一个名字。下面的工作包全部完成，并且通过第 6 节的发布关卡，才发 1.5。

E0 已经定了：1.5 不做服务器，手机端是网页，不收费（`docs/e0-servers-and-privacy.md`，Lewis 2026-11-21 说“照建议，不做服务器”）。所以这一版的“和别人一起”都在两个地方发生：用户自己发出去的文件，和家里的网络。

## 1. 目标

- **手机看店：** 在家里的网络里，配对过的手机打开一个网页，看店里在做什么，批准或拒绝店员的请求。
- **分享作品：** 一件作品存成一个文件，网页、文档、图片各用合适的格式，可以直接存进连好的网盘文件夹。
- **小店明信片：** 把自己小店的样子存成一张明信片，朋友在自己的小灯屋里打开，能进去逛一圈。
- **一起用一间店：** 同一个网络里的几个人连到一间店，有人能批准，有人只能看，各自递的委托和花费分开记。
- **隐私的承诺不变：** 还是没有我们的服务器。家里网络里的那个小网页默认关着，开了也只认配对过的设备。

## 4. 工作包

### E1 家里网络里的连接

**现状：** 主进程里没有在听的端口，也没有 WebSocket（只有 `broker.listen`，`app/main/index.ts:767`，跟网络无关）。`package.json` 里没有二维码、WebSocket 或局域网发现的库。店里的事都经一个 `send` 发给主窗口（`app/main/index.ts:71`），没有第二个收的人。只能开一个小灯屋（`app/main/index.ts:1548`）。

**设计：**

- 设置里加一个开关“手机和别的电脑可以连进来”，默认关。打开时主进程开一个小的 HTTP 服务，只听本机在家里网络里的地址，不听 `0.0.0.0` 以外的公网地址。关了就停。
- 配对：桌面上显示一个二维码和一行地址。二维码里是地址，加一段 128 位的随机钥匙，放在 `#` 后面，所以浏览器不会把它发回服务。手机打开以后，这把钥匙存在手机浏览器里。桌面上列出配对过的设备，随时能取消。
- 加密：家里网络里没有正规的 HTTPS，浏览器在 `http://192.168.x.x` 上不给 `crypto.subtle` 用。所以网页里带一个小的加密库，用配对时的钥匙把每条消息加密再发，服务这边不认加密不对的消息。
- 消息走长轮询，不用 WebSocket，少一个依赖。店里发给主窗口的事件，同时放进一个给配对设备的队列。
- 查 `Host` 头，只认本机地址，防止别的网页借浏览器打进来。配对码五次不对就停一分钟。

**做法（2026-11-21，开工前定的）：**

- 两个新库，照第 2 节第 3 条核过。加密用 `tweetnacl` 1.0.3：Unlicense，没有依赖，最后一版在 2023 年 4 月，代码早就定型，做过公开的审计。二维码用 `qrcode-generator` 2.0.4：MIT，没有依赖，2025 年 8 月还在更新。两样都只把压缩过的那一个文件打进去。**暂定（Q-E4）。**
- 开关在设置里，默认关。打开时，本机每个家里网络的 IPv4 地址各开一个服务：10.x、172.16 到 172.31、192.168.x。别的地址一概不听。
- 端口第一次打开时从 47800 往上挑一个空的，记进设置，以后都用它。**暂定（Q-E5）。**
- 每台设备有一把 32 字节的随机钥匙，和名字、加入的日子一起存在数据目录的 `devices.json` 里。点“配对一台新设备”，桌面上出一个二维码。码里是地址，`#` 后面是设备的编号和钥匙。手机打开网页，用这把钥匙加密一句话发回来，对得上就算配对好了。
- 手机发来的每条消息都用 `tweetnacl` 的 secretbox 加密，里面带一个只增不减的序号，旧的序号不认，防重放。
- 认不出的设备、解不开的消息、对不上的 `Host` 头都回 403。配对连着错五次，一分钟里不再收配对。
- 店里的事件取一个子集给手机：时间、种类、谁、那句给人看的话。手机用长轮询来取，一次最多等 25 秒。E1 的网页只做到“连上了”和一串事件，E4 再做成真的样子。

**做的时候改的：**

- 配对一成功，网页就显示“连上了”。原来要等第一次轮询回来，而店里没事时一次轮询要等 25 秒。
- 桌面上取消一台设备时，它正在等的那次轮询立刻结束，回 403。原来要等到 25 秒满了才知道。
- 二维码里的地址按 192.168、10、172 的顺序挑。这台电脑上有 WSL 的虚拟网卡 172.24.x，排在前面时手机扫了也连不上。
- 场景里的“手机”用本机装的 Chrome。Playwright 自带的那个 Chromium 没装。
- `qrcode-generator` 的包里没带许可证全文，第三方声明的测试因此不过。照 `lazy-val` 的办法，在 `scripts/notices.mjs` 里手工补上 MIT 全文，署名取自它源码头一行。

**完成标准：** 新的 `tests/lan.test.ts` 查这几样。没打开时不听，打开后只听家里网络的地址。没配对的、钥匙不对的、`Host` 不对的请求都拒。取消以后那台设备连不上。新场景 `lan`：打开开关，用 Playwright 的第二个浏览器扫码配对，收到店里的一条事件，桌面上取消，再连就被拒。中英文截图都看过。

### E4 手机网页

**现状：** 请求经 `DecisionBroker` 排队（`app/main/decision-broker.ts:13`），没有上限也不过期，发给主窗口用 `decision:request`（`app/shared/types.ts:513`），答复从 `decision:answer` 回来（`app/main/index.ts:1423`）。正在做的事经 `ai:event` 发出（`app/main/index.ts:231`），委托列表经 `commission:runs`（`app/main/index.ts:657`）。

**设计：**

- 一页就够：上面是店里现在谁在做什么，一句一行，和字幕记录一样；下面是等着答复的请求。每个请求两个按钮，同意和不同意。严重的那种只在手机上提示，要回电脑前答。
- 手机上答了，桌面上那张卡片收起来，记下是手机答的。两边同时答，先到的算。
- 不能递新委托，看不到 Key、文件夹路径和花费的明细。
- 网页开着时，来了请求就用浏览器的通知提醒一下，关了网页就收不到。在页面上写清楚。
- 网页按手机屏幕排，中英文跟着桌面的语言。用店里的纸和手写字，不加新图，只画两个按钮的小图标。

**做法（2026-11-22，开工前定的）：**

- 等着答的请求，手机在每次轮询的回答里一起拿到。只给编号、种类、谁问的、那句话、理由和选项，不给 `detail`，那里面是完整的命令和路径。请求一有增减，正在等的轮询就回来。
- 手机答题走一个新的 `POST /answer`，和 `/poll` 一样加密、核序号。严重的请求手机上只显示“回电脑前答”，服务这边也不收。
- 谁先答算谁的。`DecisionBroker` 的答复带上是在哪边答的；手机先答时，桌面那张卡片收起，字幕记录里记一行“在手机上答了”。
- 浏览器的通知要 HTTPS 才给用，家里网络的网页用不了。来了请求时改网页的标题，手机支持的话振一下。页面上写清楚：网页开着才会提醒。
- 页面用店里的纸色和边框，按手机屏幕排。手写字体不放进去，免得网页变大。**暂定。**

**完成标准：** `tests/lan.test.ts` 加：请求同时到桌面和手机，任一边答了另一边收起；严重的请求手机上答不了。场景 `phone`：用手机大小的浏览器配对，递一单会问权限的委托，在手机上同意，桌面上的卡片收起，委托做完。中英文截图都看过，手机的也看过。

**做的时候改的：**

- 场景 `phone` 里先来的是一道选颜色的问题，不是权限。手机上答它，桌面的卡片照样收起，所以没为这个场景另造一单只问权限的委托。同意和不同意的两个小图标，这次的截图里没出现。
- 委托一轮结束时没答的请求会被自动拒掉。这时也通知手机，让它的列表跟着变。
- 轮询时没带“已经看过的请求版本”的，立刻回答，不再等。E1 的网页总是不带它，现在的网页总带。
- 英文的事件行没有主语，比如 “has a question for you”。这是 E1 就有的，留到 E7 审查时一起看。

### E2 分享作品

**现状：** 作品架上能把作品存成 PDF 或 zip（`app/renderer/ui/shelf.ts:41`，`app/main/index.ts:1326`），网页先转 PDF（`app/main/print.ts:37`）。网盘文件夹的连接能把文件存进它自己的子文件夹（`app/main/folder-link.ts:78`），子文件夹的名字来自语言文件的 `saveTo`。

**设计：**

- 作品架上每件作品多一个“分享”，按作品的种类给一个默认的格式。网页存成 PDF，也能选一个所有图片都塞进去的单个网页。文档和图片照原样，别的打成 zip。
- 存到哪：默认问存在哪里。连了网盘文件夹的，多一个“存进网盘文件夹”，存进去以后提醒用户到网盘里点分享。
- 存出去的文件不带委托单、文件夹路径、店员的笔记和录制。只带作品本身。

**做法（2026-11-22，开工前定的）：**

- 作品架上的“带走”改叫“分享”。点开先选格式，默认的排第一。网页是 PDF、单个网页、压缩包；文档和图片是原样、压缩包；别的直接打成压缩包。
- 连了网盘文件夹的，选好格式再选存到哪：自己挑位置，或者存进那个网盘文件夹。存进网盘时放在连接时定的子文件夹里，名字不和已有的重，什么都不覆盖。存好后提醒用户到网盘里点分享。
- 单个网页：作品文件夹里的图片、样式、脚本都写进页面本身。从网上加载的、从文件夹外面加载的，一概去掉。页面里普通的链接照留，那是内容的一部分。
- 委托单、笔记、录制都在数据目录里，不在作品文件夹里，本来就带不出去。文字文件里出现的作品文件夹路径、用户主目录、像 Key 的字符串都抹掉，别的文件一个字节不改。

**完成标准：** `tests/share.test.ts`：每种作品的默认格式，单个网页里没有外链，存出去的文件里搜不到文件夹路径和 Key。场景 `share`：三种作品各分享一次，一次存进网盘文件夹。中英文截图都看过。

**做的时候改的：**

- 小工具的主文件是附带的那份说明，按扩展名会只把说明分享出去。所以小工具不看主文件，只给压缩包。
- 场景 `export` 从 1.4 的 D3 起就过不了：网页在工作坊里做，看的地方跟了过去，作品架却在家里，场景找不到作品架。改成从工具栏打开作品架，`share` 也这样开。
- 文档类的委托在模拟里一次做出 Word、表格和幻灯片三样，主文件是幻灯片，原样分享的就是幻灯片。场景只查它是 Office 文件。
- PDF 是把页面打印出来的，页面上写着的文件夹路径会跟着印进去，这一步不抹。单个网页、原样的文字文件和压缩包里的文字文件会抹。
- 英文的弯引号在店里的字体里前后空得很开，网盘的名字就不加引号了。
- 合并后的安全检查指出：单个网页里写进去的文字文件（比如 SVG）成了 base64，整页最后的抹除看不到里面。改成每个文件写进去之前先抹，另开一个小 PR。

### E3 小店明信片

**现状：** 店的样子由这些定：设置里的 `scene` 和 `furnish`（`app/shared/types.ts:69`，`app/shared/furnish.ts:17`），店里长出来的 `grown`（`app/shared/types.ts:750`），街上的 `town`：各店的数、街上长的、故事讲到哪（`app/shared/town.ts:13`）。

**设计：**

- 记事本里多一个“寄一张明信片”，存成一个 `.nook` 文件。里面有店名、主店是哪间、摆设、长出来的东西、街上的样子、每个街坊讲到第几章。不带作品、委托、花费和日期以外的任何东西。
- 打开明信片：记事本里“看一张明信片”，选文件。进的是只读的一间店，上面一条“你在 {name} 的小店”。能在店里和街上走一圈，没有店员在干活，什么都点不坏。按 Esc 或那条上的按钮回自己的店。
- 打开别人的文件只当数据读：只认已知的名字和范围内的数字，多的不认，坏了就说打不开。
- 明信片本身画一张小图，打开时先看到它，是手画的。

**做法（2026-11-22，开工前定的）：**

- 明信片是一个 JSON 文本文件，扩展名 `.nook`，最大 64 KB。里面有一个固定的标记和版本号，还有名字，也就是设置里的称呼，最多 40 个字。另外是主店是哪间、两间店的摆设、店里长出来的东西、做完的委托数、街上三间店各做了几单，以及每个街坊讲到第几章。
- 不带日期。长出来的东西只记有哪些，故事只记讲到第几章。街上的样子按这些数画，和自己店里的画法一样。
- 读的时候先看大小，超过 64 KB 不读。再看标记和版本。每个键和每个编号都要认识，每个数都要是整数并且在范围里，多一个不认识的键也不开。打不开时只说一句，自己的店什么都不动。
- 看明信片开一个单独的窗口，盖在店上面，关了就回到自己的店。这个窗口有自己的 preload，只给两样：明信片的内容和“回家”。它碰不到委托、设置和记事本，所以在里面点什么都改不了自己的店。自己店里正在做的委托照做。**暂定。**
- 窗口里先看到一张明信片：纸、邮票、邮戳，中间是那间店的门面。门面取自街上已有的画，邮票和邮戳用样式画，不加新图。**暂定。** 点“进去看看”进店。
- 店上面一条“你在 {name} 的小店”，能到街上走，街上别的店不进。店员在，但不干活，客人和讲故事的街坊不来。按 Esc 或那条上的按钮回家。

**完成标准：** `tests/postcard.test.ts` 查存出去再读回来一样。不认识的名字、超范围的数、太大的文件、不是明信片的文件都打不开，也不会改坏自己的店。场景 `postcard`：两个数据文件夹，一个寄，一个看，看完回到自己的店，自己的东西都没变。中英文截图都看过。

**做的时候改的：**

- 看明信片的窗口用的 preload 只引入 Electron。沙箱里的 preload 读不了第二个文件，可两个 preload 一起打包时，共用的代码会被拆成单独一个文件。所以它的频道名直接写在里面，测试查这几个名字和 `IPC` 里的一样。
- 英文邮票上的 “Lamplight Nook” 放不下，邮票加宽了一点，字也改小了。
- 记事本里的两个按钮和店上那条里的按钮，都用店里纸片按钮的样子。
- 场景里除了不是明信片的文件，还试了一张多一个键的明信片，两样都打不开，也不出窗口。在别人店里的画面上随手点了五处，回来以后自己的 `memory.json` 和 `settings.json` 一个字节都没变。

### E6 分享出去的东西带什么

**设计：** 把分享文件和明信片里带什么、不带什么列成一张表，写进 `docs/privacy-1.5.md` 和商店说明。加一个测试，把两种文件都拆开，查不到 Key、文件夹路径、委托内容和连接。商店政策里管用户发布内容和隐私的条款再对一遍。

**做法（2026-11-22，开工前定的）：**

### E5 一起用一间店

**现状：** 花费按作品文件夹和会话记（`app/main/spend.ts:19`），项目的花费是把文件夹加起来（`app/main/index.ts:574-576`）。没有“人”的概念。

**设计：**

- 配对时给设备定一个角色：只能看，能批准，能递委托。手机默认只能看和批准。
- 能递委托的人用电脑上的浏览器打开同一个网页，多一张委托单，样子照桌面上的简化。委托记下是谁递的，花费也按人记。账本里多一列“谁”，桌面上的人算“店主”。
- 月度上限照旧管整间店。店主可以给每个人设一个自己的上限。
- 同时开工的委托数照旧由店里定，别人递的也排队。

**做法（2026-11-23，开工前定的）：**

- 每台配对过的设备多一个角色，存在 `devices.json` 里：只能看、能批准、能递委托。新配对的默认是能批准，E4 以前配对的也算能批准。店主在设置的设备列表里给每台改角色。
- 服务这边管角色，网页只是跟着显示。只能看的设备，`/answer` 回 403。新开一个 `POST /commission`，和 `/answer` 一样加密、核序号，只有能递委托的设备收。每次轮询的回答里带上这台设备的角色。
- 网页上的委托单只有两样：想做什么，和做哪一种。只列不用选文件的几种，因为网页拿不到这台电脑上的文件。递来的委托走桌面上新委托的同一条路：先问上限，再排队，同时开工几单照旧由店里定。结果卡在桌面上出来，和定时委托一样。
- 委托单里记下是谁递的：设备的编号和名字。账本的每一笔也记上是谁，桌面上递的不记，算店主。
- 店主可以给每台能递委托的设备设一个月度上限，可选不设、1、2、5、10 美元，存在 `devices.json` 里。它和整间店的月度上限、项目上限一起管。开工前不够就不开，做到一半到了就停，停的原因写“这个人的上限到了”。**暂定。**
- 设置里的月度账本，每个月下面按人分几行：店主一行，每台设备一行，都写名字和花了多少。取消了的设备，名字跟着设备一起删了，账上写“已取消的设备”。
- 真 Key 那一单用应用里存着的 Key。先备份数据文件夹，在浏览器里递一单最便宜的网页，店主在桌面上批准，看账本里按人分开。

**做的时候改的：**

- 角色和上限在设置的设备列表里选，每台一个下拉框。选了能递委托，旁边再多一个上限的下拉框。列表每 2 秒刷新一次，正在选的时候不刷，不然下拉框会收起来。
- 网页上的委托单列的是不用选文件、也不用选照片的那几种，在 `FROM_AFAR` 里。网页先问店里，店里说收了才写“递进去了”；上限到了，就当场写“上限用完了”，什么都不开工。
- 能递委托的设备默认不单独设上限，整间店的月度上限照管。**暂定。**
- 一台设备排着队的委托还没开工，设备就被取消了。这时候它按个人上限用完来算，开不了工。这是提交以后安全审查提的：原来查不到这台设备，就当它没有上限。
- 场景 `team` 用了会问一个问题的剧本，好让只能看的手机有东西可看。账本是开店时读进来的，所以场景测上限时先关店，往账上添一笔，再开店。手机网页那边不用重新配对。
- 真 Key 那一单（2026-11-23）：先把数据文件夹备份到 `~/.agents/backups/lamplight-userdata-before-e5-real-2026-11-23`。分支的构建用应用里存着的 Key，在 Chrome 里递了一单最简单的网页，花了 $0.24。账本里分成“在电脑上 $4.63”和“设备 1 $0.24”。这一单 Claude 一个请求都没问，所以“店主在桌面上批准”只在场景里查过。跑完把设备取消了，家里网络也关回去了。

**完成标准：** `tests/team.test.ts`：只能看的人答不了请求，递不了委托；按人记的账加起来等于整间店的；个人上限到了就停。场景 `team`：一部手机只看，一个浏览器递一单，店主批准，账本里按人分开。真 Key 约 $2：一个浏览器递一单真的委托。中英文截图都看过。

### E7 家里网络那个网页的安全审查

**设计：** 照 1.3 那几轮安全审查的做法，把 E1、E4、E5 开口的地方逐条过一遍。要过的有这些：只听家里网络、`Host` 头、配对码的次数、钥匙存哪、取消以后是否立刻断。还有消息重放、大请求、慢请求，日志里会不会留下钥匙。网页本身是明文 HTTP 送到手机的，同一个网络里有人改得了它。这一条写进说明，作为已知的限制。

**做法（2026-11-23，开工前定的）：**

- 照上面列的逐条过，再加 E5 新开的四处：角色在服务这边管，`/commission` 的表单检查，个人上限，已取消设备排着队的委托。
- 每一条读代码，写结论。要改的先写一个会失败的测试，看着它因为缺这个行为而失败，再改。
- 网页走明文 HTTP 这一条改不了，写进应用里的隐私说明和 `docs/privacy-1.5.md`，作为已知的限制。

**结论：**

| 要过的 | 现在的样子 | 结论 |
|---|---|---|
| 只听家里网络 | `homeAddresses`（`app/main/lan.ts:45`）只取 10、172.16 到 172.31、192.168 开头的 IPv4。本机回环、链路本地和公网地址都不听 | 没问题。连着 VPN 时，VPN 发的 10.x 地址也算家里网络，同一个 VPN 里的人能打开网页，但没配对进不来。写进已知的限制，不改 |
| `Host` 头 | 只认本机地址加端口，一字不差（`lan.ts:208`） | 没问题。别的网页借浏览器换个域名打进来，会被挡掉 |
| 配对码 | 码里的设备编号 64 位，钥匙 256 位，猜不出来。连着错五次停一分钟 | 要改。原来码一直有效，被人拍了照或者复制了地址，什么时候都能拿来用。现在十分钟内只能用一次。配对那一刻店里另给这台设备一把新钥匙，码里那把从此打不开任何东西 |
| 停一分钟 | 同一个网络里有人每分钟乱试五次，别人就一直配对不上 | 只挡配对，看和答都不受影响。不改 |
| 钥匙存哪 | 数据文件夹里的 `devices.json`，没加密。设备列表、诊断包和日志里都没有 | 不改。读得到这个文件的人，数据文件夹里别的东西也都读得到 |
| 取消以后 | 下一条消息回 403，正在等的轮询马上结束 | 要改。排着队还没开工的委托留在队里不走，只是因为上限算成 `GONE_USD` 才一直开不了工。现在取消设备时一起叫停。已经开工的那单照做，店主在桌面上随时能停 |
| 重放 | 手机发来的每条消息带一个只增不减的序号，存在 `devices.json` 里，重开应用也记得 | 没问题。店里回给手机的话不带序号，网络里的人能把旧回话再放一遍。这算在明文 HTTP 那条限制里 |
| 大请求 | 超过 16 KB 就断开（`lan.ts:274`） | 没问题，补了测试 |
| 慢请求 | 原来用 Node 的默认值，一个请求能拖五分钟才断，拖住的连接多了店里的网页就慢 | 要改。十秒还没送完就断开（`lan.ts:121`）。长轮询是请求送到以后店里在等，不受影响 |
| 日志 | 只记端口和地址的个数（`app/main/index.ts:1181`），没有地址、设备编号和钥匙 | 没问题。诊断包里只有日志和设置，没有 `devices.json` |
| 网页里的字 | 店里的话都用 `textContent` 放进去，只有两个固定的小图标用 `innerHTML` | 没问题。另外加了内容安全策略：网页只能连回店里，也不能被别的网页框进去。框进去的话，别人的网页能骗人点到按钮 |
| 明文 HTTP | 网页是明文送到手机的，同一个网络里有人改得了 | 改不了。写进隐私说明，中英文都有，作为已知的限制 |
| 角色 | 只能看的设备 `/answer` 回 403（`lan.ts:241`），只有能递委托的才收 `/commission`（`lan.ts:246`），严重的请求手机上答不了 | 没问题，`tests/team.test.ts` 查过 |
| 委托单 | 想做什么去掉首尾空白以后不能空，不过 2000 字。种类只能是 `FROM_AFAR` 里的（`lan.ts:249`） | 没问题 |
| 个人上限 | 递进来时查一次，排到开工时再查一次，做到一半到了就停 | 没问题 |
| 已取消设备排着的委托 | 查不到设备时，个人上限算成 `GONE_USD`，开不了工 | 核过，没问题。挪到 `app/main/budget.ts:21` 的 `personCapUsd`，补了测试 |
| 英文事件行没有主语 | E4 留下的 | 不是安全问题。手机拿到的只有代理的编号，哪个店员在说话是桌面的场景里才分的。1.5 不改。**暂定** |

**做的时候改的：**

- 设置里的二维码，那台设备一配对好就收起来。码下面的提示改成“十分钟内用手机扫这个码，只能配对一台，用一次”。
- 隐私说明的日期改成 11 月 23 日，加了明文 HTTP 那一段。

**完成标准：** 每一条有结论，要改的改了并有测试，写进本文。
