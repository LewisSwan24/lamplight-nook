# 小灯屋 1.6 街上热闹起来

2026-11-25 写，照 `docs/road-to-2.0.md` 第 4 节细化。Lewis 当天定了三件事。一是计划在原来的会话里写，开发交给新会话。二是开发要有至少两万行新增，但不为了增而增。三是选模型和接别的接口都放进 1.6，因为「不可能默认所有人都用 CLAUDE 模型」。

## 1. 目标

1.6 做完，街上有人走动，面包房和邮局能进去，面包师和邮差各有自己的店和故事。另外，用户能选用哪个模型，也能把店员接到 Anthropic 以外的接口上。

## 2. 流程

照 `docs/road-to-2.0.md` 第 9 节。和它不一样的有三处：

1. **分支。** 1.5 还没发布，`release-1.6` 先从 `release-1.5` 的 `93e85a7` 或更新的提交开。1.5 发布以后，把 `release-1.5` 并进来。
2. **两万行。** Lewis 要开发新增至少两万行。只算有用的东西：代码、测试、台词、故事、文档。锁文件、快照、图片和照抄的东西不算。1.6 做完不够两万行，就接着照路线图写 1.7 的计划，接着做。每个包的 PR 说明里写上这个包新增了多少行。
3. **新会话开发。** 本文合并以后，开发在新会话里一个包一个包往下做，Lewis 随时可以叫停或者改方向。

## 4. 工作包

### F0 内容管线

**现状：** 没有清点内容的脚本，`scripts/` 里只有打包、许可、素材、录制和冒烟测试几样。台词靠 `tests/lines.test.ts` 查写法（规则在 `app/renderer/translator/lines.ts:136-141`）。故事靠 `tests/stories.test.ts` 查章数（`:23-27`），美术靠 `tests/art-sources.test.ts` 查来源。三样各管各的，没有一处看得到总数。

**设计：** 一个脚本 `scripts/content.mjs`，`npm run content` 跑。脚本先数人和地方：委托种类、能进的店、店员、客人、讲故事的人和章数。再数东西：长出来的东西、节日、图的张数，还有台词的行数，按文件分中英文。顺带查四样：中英文的键一样多，每张图都在美术清单里。故事的解锁条件不打架，每间店都有自己的台词文件。结果写进 `docs/content.md`，一张表加上和上次比多了什么。

**完成标准：** `tests/content.test.ts` 先写，查清点脚本数得对（拿一个小样本目录来数）、查得出缺的英文台词和不在清单里的图。`docs/content.md` 第一版按 `93e85a7` 的样子生成。

**做法：** `scripts/content.mjs` 用 tsx 跑，代码里的表从 `app/shared` 的模块直接读，客人另加了一张 `GUESTS` 表。台词按文件数“条”和“句”：一条是一段台词、一段闲聊或一章故事，一句是一个气泡。美术清单是 `docs/art-*.md` 的表加上 1.3 以前的图。故事查三样：单数一章比一章多，留下的东西不重样，代码和 `lines/stories.yaml` 的章数、留下的东西对得上。两位讲故事的人同一单解锁只记成提醒，因为陈奶奶和小禾的第 5 章都在第 50 单。再数一遍结果没变，文件不动，上次的变化留着。`npm run content -- --check` 只比不写，给发布关卡用。`tests/content.test.ts` 也查真的内容：四样都过，`docs/content.md` 和数出来的一样。

### F6 选模型

**现状：** 委托没有指定模型，用的是 Claude Code 自己的默认值（`app/main/agent-runner.ts:239-254` 的 `query()` 没传 `model`）。只有商量写死了 Haiku（`app/main/consult.ts:11`）。账本按返回的模型名估价，表里只有 Opus、Sonnet、Haiku 三档（`app/main/prices.ts:9-18`）。设置里没有模型这一项。

**设计：**

- 设置的“开工”页加一项“店员用哪个模型”：三档，写成“最好”“均衡”“省钱”，对应 Opus、Sonnet、Haiku。每档旁边写大概多少钱一单，从账本里同档的平均值算，没有就用价目表估。默认“均衡”。**暂定（Q-F7）。**
- 委托单上的“更多”里也能为这一单改，只管这一单。
- 定时委托记下建的时候选的模型。
- 商量跟着设置走，但最高用“均衡”。商量不需要最好的模型。

**完成标准：** 单元测试查四件事。设置存取模型，并拒收别的值。店员启动时带上选的模型。账本按实际模型算钱，委托单上改的只管这一单。场景 `model`：设置里改成“省钱”，递一单，账本记的是 Haiku 的价。真 Key 约 $2：三档各跑一单最小的委托，看账本和实际花费对得上。

**做法：**

- 三档写在 `app/shared/models.ts`，存的是 Claude Code 自己的别名 `opus`、`sonnet`、`haiku`，换了新模型不用改代码。设置里存 `modelTier`，读到别的值按“均衡”算。
- 委托单的“更多”里有一个下拉框，默认写着“照设置（省钱）”这样的字。选了别的只记在这一单的 `form.model` 上。改一版时不跟着它，照当时的设置。
- 定时委托建的时候把当时的档记进它的单子，以后每一轮都用这一档，设置改了也不变。
- 商量照设置走，“最好”降成“均衡”。商量原来写死 Haiku，现在默认用 Sonnet，上限还是 $0.10。
- 店员启动时把模型交给 Claude Code，开头那条消息里报回实际用的模型名，账本每一行记下来。设置里每档旁边的价钱，从账本里同档的委托算平均，每单的几轮合在一起算。账本里没有这一档，就按一单中等的委托估：两万输入、一万五输出、四万写缓存、四十万读缓存，标“估的”。
- 替身 Claude 认 `--model`，报回 `claude-haiku-sim` 这样的名字，Haiku 一步的钱是平常的三分之一，Opus 是三分之五，和价目表一样。
- 真 Key 那一单还没跑，等 Lewis 点头，和后面几个包的一起报。

### F7 接别的接口

**现状：** 只认 Anthropic 的 Key：存在应用里的那把，没有就读 `ANTHROPIC_API_KEY`（`app/main/api-key.ts:77-82`）。用 Key 时，启动店员之前会把所有 `ANTHROPIC_*`、`CLAUDE_CODE_*` 变量清掉（`api-key.ts:86-95`），`ANTHROPIC_BASE_URL` 也清了。这是为了让打包版用不到用户自己的 Claude 登录，也就没法改接别的地方。Key 用系统自带的加密存（`api-key.ts:5`）。

**设计：**

- 设置里的 Key 那一项改成“接口”，选一家，再填这一家要的东西：
  - **Anthropic**：和现在一样，只填 Key。
  - **兼容 Anthropic 接口的服务**：填接口地址、Key、模型名。预设几家已知提供兼容接口的：DeepSeek、Kimi、智谱 GLM、阿里百炼、OpenRouter。地址和模型名开工时逐家到官方文档上核对，核不到的不放。**暂定（Q-F8）。**
  - **AWS Bedrock** 和 **Google Vertex**：照 Claude Code 自己的接法，填区域、项目和凭据。
  - **只说 OpenAI 格式的服务**：Claude Code 接不了，要先过一层转换网关，比如 LiteLLM。这一档只写说明，教用户自己架网关，再按“兼容接口”填网关的地址。
- 启动店员时，只把选中那一家要的变量放进去，比如 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_MODEL`。其余照旧清掉。
- 每家的 Key 分开加密存，切换不丢。Key 和带 Key 的地址都不进日志、诊断包和账本。
- 接口地址只收 HTTPS，本机地址（`localhost`、`127.0.0.1`）可以用 HTTP，给本机的网关用。
- 存 Key 时照现在的做法，发一次最小的请求，确认这一家能用。不通就当场说是地址、Key 还是模型名不对。
- 别家的价格应用不知道。选了兼容接口，就要填每百万输入、输出词元的单价，填了上限和账本才算得出钱。不填就不让开工，因为月度上限靠估价管着。**暂定（Q-F9）。**
- 别家的模型用工具的本事参差不齐，选了以后设置里标一句“试用：店员可能做不完复杂的委托”。
- 隐私说明和商店的隐私问卷改写：委托内容发给用户选的那一家，适用那一家的条款。

**完成标准：**

- 单元测试：
  - 每一家只放它要的变量，别的都清掉。
  - 非本机的 HTTP 地址不收。
  - Key 不出现在日志和诊断包里。
  - 没填单价不让开工，填了以后按单价算钱。
- 场景 `provider`：在 `tools/sim/` 里写一个假的兼容接口，在本机起来。设置里选“兼容接口”，填这个地址，递一单。替身 Claude 收到的变量要对，账本按填的单价记。
- 真 Key：
  - Anthropic 约 $2。
  - 别家用 Lewis 自己的 Key，在应用的设置里由 Lewis 自己填，开发会话不读、不问、不打印 Key。先报预算再跑。

### F1 面包房开门

**现状：** 街上已经画着面包房的门面（`scripts/art/town.py`，位置在 `assets/sprites/town.json`），`ShopId` 里也有 `bakery`（`app/shared/town.ts:4`）。点它回“还没开”，因为能进的店只有 `ROOMS` 里那五间（`app/renderer/game/town.ts:20-30`）。面包师是常来的客人，店里闲着时来柜台聊几句，有委托就走（`app/renderer/game/guests.ts:8-17`）。

**设计：**

- 店里的样子用 `scripts/art/bakery.py` 拼：`1_Interiors` 的 `12_Kitchen`、`16_Grocery_store`，`3_Animated_objects` 里的烤箱和冷柜。素材包里没有面包，面包、面包篮、价目黑板由脚本手画。
- 两种新委托，都在面包房做：
  - **菜单**：给小店、家宴或者聚会做一页菜单或价目表，出一页图和一份 PDF。
  - **食谱**：把一道菜写成能照着做的食谱，有用料、步骤、要注意的地方。出一份文档。

**完成标准：** 单元测试：店的表、店员、派单都认得面包房，两种委托的提示词快照。场景 `bakery`：从街上进面包房，递一单菜单，做完，中英文截图都看过。真 Key 约 $4：两种各一单。

### F2 邮局开门

### F3 街上的行人

**现状：** 街上只有真的来往：来串门的客人，和出门跑腿的小橘（`app/renderer/game/passers.ts:2-19`，`app/renderer/game/StreetScene.ts:42-43,115,141`）。没有随便走动的人。素材包的 `2_Characters` 里有 20 个现成角色和 328 个旧版单人角色，没有打伞的。

**设计：**

- 街上随时有两到五个行人，从一头走到另一头，有的在门口停一停。人数跟着时辰变：早晚多，深夜没有。
- 下雨时人少，走得快。素材里没有伞，伞由脚本手画，叠在行人头上。
- 行人不进店，不说话。点一下会转头看一眼。
- 节省电脑：街不在眼前时行人不动（照 D8 的省电办法）。

**完成标准：** 单元测试：人数按时辰和天气算对；街不在眼前时不更新。场景 `street` 加一段：白天、深夜、下雨各截一张图，中英文都看过。
