# 小灯屋 1.6 街上热闹起来

2026-11-25 写，照 `docs/road-to-2.0.md` 第 4 节细化。Lewis 当天定了三件事。一是计划在原来的会话里写，开发交给新会话。二是开发要有至少两万行新增，但不为了增而增。三是选模型和接别的接口都放进 1.6，因为「不可能默认所有人都用 CLAUDE 模型」。

## 1. 目标

1.6 做完，街上有人走动，面包房和邮局能进去，面包师和邮差各有自己的店和故事。另外，用户能选用哪个模型，也能把店员接到 Anthropic 以外的接口上。

## 2. 流程

照 `docs/road-to-2.0.md` 第 9 节。和它不一样的有三处：

1. **分支。** 1.5 还没发布，`release-1.6` 先从 `release-1.5` 的 `93e85a7` 或更新的提交开。1.5 发布以后，把 `release-1.5` 并进来。
2. **两万行。** Lewis 要开发新增至少两万行。只算有用的东西：代码、测试、台词、故事、文档。锁文件、快照、图片和照抄的东西不算。1.6 做完不够两万行，就接着照路线图写 1.7 的计划，接着做。每个包的 PR 说明里写上这个包新增了多少行。
3. **新会话开发。** 本文合并以后，开发在新会话里一个包一个包往下做，Lewis 随时可以叫停或者改方向。

## 4. 工作包

### F0 内容管线

**现状：** 没有清点内容的脚本，`scripts/` 里只有打包、许可、素材、录制和冒烟测试几样。台词靠 `tests/lines.test.ts` 查写法（规则在 `app/renderer/translator/lines.ts:136-141`）。故事靠 `tests/stories.test.ts` 查章数（`:23-27`），美术靠 `tests/art-sources.test.ts` 查来源。三样各管各的，没有一处看得到总数。

**设计：** 一个脚本 `scripts/content.mjs`，`npm run content` 跑。脚本先数人和地方：委托种类、能进的店、店员、客人、讲故事的人和章数。再数东西：长出来的东西、节日、图的张数，还有台词的行数，按文件分中英文。顺带查四样：中英文的键一样多，每张图都在美术清单里。故事的解锁条件不打架，每间店都有自己的台词文件。结果写进 `docs/content.md`，一张表加上和上次比多了什么。

**完成标准：** `tests/content.test.ts` 先写，查清点脚本数得对（拿一个小样本目录来数）、查得出缺的英文台词和不在清单里的图。`docs/content.md` 第一版按 `93e85a7` 的样子生成。

**做法：** `scripts/content.mjs` 用 tsx 跑，代码里的表从 `app/shared` 的模块直接读，客人另加了一张 `GUESTS` 表。台词按文件数“条”和“句”：一条是一段台词、一段闲聊或一章故事，一句是一个气泡。美术清单是 `docs/art-*.md` 的表加上 1.3 以前的图。故事查三样：单数一章比一章多，留下的东西不重样，代码和 `lines/stories.yaml` 的章数、留下的东西对得上。两位讲故事的人同一单解锁只记成提醒，因为陈奶奶和小禾的第 5 章都在第 50 单。再数一遍结果没变，文件不动，上次的变化留着。`npm run content -- --check` 只比不写，给发布关卡用。`tests/content.test.ts` 也查真的内容：四样都过，`docs/content.md` 和数出来的一样。

### F6 选模型

**现状：** 委托没有指定模型，用的是 Claude Code 自己的默认值（`app/main/agent-runner.ts:239-254` 的 `query()` 没传 `model`）。只有商量写死了 Haiku（`app/main/consult.ts:11`）。账本按返回的模型名估价，表里只有 Opus、Sonnet、Haiku 三档（`app/main/prices.ts:9-18`）。设置里没有模型这一项。

**设计：**

- 设置的“开工”页加一项“店员用哪个模型”：三档，写成“最好”“均衡”“省钱”，对应 Opus、Sonnet、Haiku。每档旁边写大概多少钱一单，从账本里同档的平均值算，没有就用价目表估。默认“均衡”。**暂定（Q-F7）。**
- 委托单上的“更多”里也能为这一单改，只管这一单。
- 定时委托记下建的时候选的模型。
- 商量跟着设置走，但最高用“均衡”。商量不需要最好的模型。

**完成标准：** 单元测试查四件事。设置存取模型，并拒收别的值。店员启动时带上选的模型。账本按实际模型算钱，委托单上改的只管这一单。场景 `model`：设置里改成“省钱”，递一单，账本记的是 Haiku 的价。真 Key 约 $2：三档各跑一单最小的委托，看账本和实际花费对得上。

**做法：**

- 三档写在 `app/shared/models.ts`，存的是 Claude Code 自己的别名 `opus`、`sonnet`、`haiku`，换了新模型不用改代码。设置里存 `modelTier`，读到别的值按“均衡”算。
- 委托单的“更多”里有一个下拉框，默认写着“照设置（省钱）”这样的字。选了别的只记在这一单的 `form.model` 上。改一版时不跟着它，照当时的设置。
- 定时委托建的时候把当时的档记进它的单子，以后每一轮都用这一档，设置改了也不变。
- 商量照设置走，“最好”降成“均衡”。商量原来写死 Haiku，现在默认用 Sonnet，上限还是 $0.10。
- 店员启动时把模型交给 Claude Code，开头那条消息里报回实际用的模型名，账本每一行记下来。设置里每档旁边的价钱，从账本里同档的委托算平均，每单的几轮合在一起算。账本里没有这一档，就按一单中等的委托估：两万输入、一万五输出、四万写缓存、四十万读缓存，标“估的”。
- 替身 Claude 认 `--model`，报回 `claude-haiku-sim` 这样的名字，Haiku 一步的钱是平常的三分之一，Opus 是三分之五，和价目表一样。
- 真 Key 那一单还没跑，等 Lewis 点头，和后面几个包的一起报。

### F7 接别的接口

**现状：** 只认 Anthropic 的 Key：存在应用里的那把，没有就读 `ANTHROPIC_API_KEY`（`app/main/api-key.ts:77-82`）。用 Key 时，启动店员之前会把所有 `ANTHROPIC_*`、`CLAUDE_CODE_*` 变量清掉（`api-key.ts:86-95`），`ANTHROPIC_BASE_URL` 也清了。这是为了让打包版用不到用户自己的 Claude 登录，也就没法改接别的地方。Key 用系统自带的加密存（`api-key.ts:5`）。

**设计：**

- 设置里的 Key 那一项改成“接口”，选一家，再填这一家要的东西：
  - **Anthropic**：和现在一样，只填 Key。
  - **兼容 Anthropic 接口的服务**：填接口地址、Key、模型名。预设几家已知提供兼容接口的：DeepSeek、Kimi、智谱 GLM、阿里百炼、OpenRouter。地址和模型名开工时逐家到官方文档上核对，核不到的不放。**暂定（Q-F8）。**
  - **AWS Bedrock** 和 **Google Vertex**：照 Claude Code 自己的接法，填区域、项目和凭据。
  - **只说 OpenAI 格式的服务**：Claude Code 接不了，要先过一层转换网关，比如 LiteLLM。这一档只写说明，教用户自己架网关，再按“兼容接口”填网关的地址。
- 启动店员时，只把选中那一家要的变量放进去，比如 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_MODEL`。其余照旧清掉。
- 每家的 Key 分开加密存，切换不丢。Key 和带 Key 的地址都不进日志、诊断包和账本。
- 接口地址只收 HTTPS，本机地址（`localhost`、`127.0.0.1`）可以用 HTTP，给本机的网关用。
- 存 Key 时照现在的做法，发一次最小的请求，确认这一家能用。不通就当场说是地址、Key 还是模型名不对。
- 别家的价格应用不知道。选了兼容接口，就要填每百万输入、输出词元的单价，填了上限和账本才算得出钱。不填就不让开工，因为月度上限靠估价管着。**暂定（Q-F9）。**
- 别家的模型用工具的本事参差不齐，选了以后设置里标一句“试用：店员可能做不完复杂的委托”。
- 隐私说明和商店的隐私问卷改写：委托内容发给用户选的那一家，适用那一家的条款。

**完成标准：**

- 单元测试：
  - 每一家只放它要的变量，别的都清掉。
  - 非本机的 HTTP 地址不收。
  - Key 不出现在日志和诊断包里。
  - 没填单价不让开工，填了以后按单价算钱。
- 场景 `provider`：在 `tools/sim/` 里写一个假的兼容接口，在本机起来。设置里选“兼容接口”，填这个地址，递一单。替身 Claude 收到的变量要对，账本按填的单价记。
- 真 Key：
  - Anthropic 约 $2。
  - 别家用 Lewis 自己的 Key，在应用的设置里由 Lewis 自己填，开发会话不读、不问、不打印 Key。先报预算再跑。

**做法：**

- 预设七家，2026-11-25 逐家读过官方的 Claude Code 接入说明（见下表），Key 都放在 `ANTHROPIC_AUTH_TOKEN` 里。设置页上的说明页面没有一家写价钱，所以单价一律由用户填。
- 阿里百炼的说明页给了两个按量付费的地址：正文里的地址带用户自己的业务空间编号，FAQ 里是公用的 `dashscope` 地址。预设用公用的这个，用户可以自己改。Kimi 只核到国际站，国内站没放。
- 选了别家，Claude Code 只拿到这一家要的变量。机器上原有的 `ANTHROPIC_*`、`CLAUDE_CODE_*`、`AWS_*` 和 Google Cloud 的变量一律清掉，用 Anthropic 时也一样。兼容接口把三个别名都指到填的模型上，快一点的模型只给 Haiku 那一档。
- Bedrock 只填区域和 Key：Bedrock 的 API Key，或者写成“访问密钥 ID:私密访问密钥”。Vertex 填区域、项目和服务账号密钥文件的路径，文件留在原处，小灯屋不存它的内容。两家都照 Claude Code 文档的写法，F6 的三档在这两家照样能用。
- 每家的 Key 加密存在数据文件夹的 `keys/` 下，一家一个文件，Anthropic 的还在原来的 `api-key.bin`。读过或存过的 Key 都交给日志的打码。接口地址不收带用户名、密码、问号或井号的写法，所以地址里不会夹着 Key。
- 存兼容接口时发一条一个词元的消息，`Authorization` 和 `x-api-key` 都带上。回 401、403 是 Key 不对；回 400 或 404 且错误里提到模型，是模型名不对；别的 404 或连不上是地址不对。别的回答先存下，标“还没核对”。
- Claude Code 对不认识的模型报的钱不可信，它的文档也这么说。兼容接口的一单，钱由小灯屋按词元和用户填的单价算，读缓存也按输入的价算，宁多勿少。每一轮的上限也由小灯屋管，超了就停。账本里这种行单独记，不和 Claude Code 报的总数相抵。
- 场景 `provider` 在本机起一个假的兼容接口（`tools/sim/compatible.mjs`）。替身 Claude 收到地址时会把拿到的变量写下来，再往这个地址发一条请求。
- 隐私说明和商店介绍都加了一段：选了别家，委托内容就发给那一家，适用那一家的条款。
- 真 Key 还没跑：Anthropic 约 $2，别家要 Lewis 自己在应用里填 Key。

### F1 面包房开门

### F2 邮局开门

**现状：** 邮局的门面和面包房一样，画着但进不去。邮差是常来的客人，也送新版本的信和 C8 的寄取（`app/shared/types.ts:55,296,653-656`）。素材包里有整套邮局：`Modern_Exteriors_16x16/ME_Theme_Sorter_16x16/22_Post_Office_Singles_16x16` 45 件，三种邮局的门，邮差的衣服、帽子和邮包（`Character_Generator_Addons_16x16`）。

**设计：**

- 照 F1 的路子加一间店，店主是邮差。
- 两种新委托：
  - **贺卡**：节日、生日、感谢的卡片，出一张图，可以印。
  - **简报**：给家里、社团或小团队的一页简报，出一份文档或 PDF。
- 收到的明信片在邮局留底：E3 打开过的明信片，邮局的墙上挂一张小卡，点了能再看。只记谁寄的和店的样子，跟 E3 一样不带日期。
- 新版本的信和 C8 的寄取照旧由邮差送，只是他从邮局出门。

**完成标准：** 单元测试同 F1，加明信片留底的存取。场景 `post`：进邮局，递一单贺卡，墙上看得到之前打开过的明信片。真 Key 约 $4。

**做法：**

- 邮局是第五间街上的店，各张表照 F1 加上 `post`。店主是新的店员 `axin`，中文还叫阿信，英文叫 Pip，行走图和客人邮差同一套搭配，背着邮包。客人 `postman` 照旧来主店，新版本的信和 C8 的寄取也照旧由他送，跟桂姨一样两边都在。
- 屋里的样子：灰白格子地砖，墙上半截奶白、下半截绿色墙裙。黑板右边是分信格，阿信在那儿干活；分信格上面的墙上钉着一块软木板。书架的位置是一个放包裹的木架，阅读桌是打包桌，角落是邮筒。柜台是手画的木柜台，绿色柜面，一头放秤，一头放邮戳。邮筒在素材包里是红的，脚本染成绿色。邮资用粉笔写在黑板上。
- **贺卡**交回一张图：明信片横放（1748×1240），说了要发手机就是方图，另存一份 PDF。祝福照用户给的写；没给就写一两句平实的话，不编名字、年纪、日子和共同的回忆。结果卡的缩略图就是贺卡那张图。
- **简报**交回一份 Word，再排一页 A4 网页存成 PDF，好贴出去。开头是简报名和期数，每条消息一个小标题，要紧的在前；日子、时间、地点最后单列一张表。只写用户给的事，缺的用方括号留空。
- 明信片留底：E3 打开过的明信片存在数据目录的 `postcards.json` 里。新的在前，同一张再打开就挪到最前，最多留 6 张，不带日期。每次读都按陌生人的文件重新验过，验不过的就丢掉。软木板上按顺序钉着小卡，邮票的颜色看寄信人的店是咖啡馆还是书房。指着一张显示是谁寄的，点了就弹出那张明信片，再逛一遍。一张都没有时，指着软木板说还没收到过，点了阿信也这么说。
- 贺卡带来主店侧窗上的一串贺卡和花店的芳姐；简报做满两份带来窗台上的一摞简报和居委会的吴阿姨。两位客人的家常话、下雨天和四季的话照 F1 的数量写，中英文都有。
- 邮局自己长的四样：裱起来的第一张邮票、绿萝、铜邮号、送信路线图。节日时墙上钉一个航空信封，节日画在信封正面。街上的店招画的是信封。

- 场景 `post`：数据目录里先放两张明信片，从街上进邮局，屋里只有阿信，软木板上两张卡。指着最新那张显示寄信人，点了弹出那张明信片。递一单贺卡，查图是明信片大小、旁边有 PDF、包裹上写着阿信。再递一单简报，查 Word 和 PDF。街上的场景原来要点一间没开的店，现在每间都开了，那一段删了。

### F3 街上的行人

**现状：** 街上只有真的来往：来串门的客人，和出门跑腿的小橘（`app/renderer/game/passers.ts:2-19`，`app/renderer/game/StreetScene.ts:42-43,115,141`）。没有随便走动的人。素材包的 `2_Characters` 里有 20 个现成角色和 328 个旧版单人角色，没有打伞的。

**设计：**

- 街上随时有两到五个行人，从一头走到另一头，有的在门口停一停。人数跟着时辰变：早晚多，深夜没有。
- 下雨时人少，走得快。素材里没有伞，伞由脚本手画，叠在行人头上。
- 行人不进店，不说话。点一下会转头看一眼。
- 节省电脑：街不在眼前时行人不动（照 D8 的省电办法）。

**完成标准：** 单元测试：人数按时辰和天气算对；街不在眼前时不更新。场景 `street` 加一段：白天、深夜、下雨各截一张图，中英文都看过。

**做法：**

- 行人的走法写在 `app/renderer/game/crowd.ts`，不碰画面，只管谁在哪儿、往哪儿走。人数看时辰。早上七点到十点、傍晚五点到八点各五个，白天三个。晚上八点以后两个，夜里十一点到早上六点一个都没有。下雨下雪减半，至少留一个；下雨走快一半。
- 街第一次出现在眼前时，视野里已经有人在走，不是从空街慢慢冒出来。之后有人走出视野就放走，人数不够时隔一会儿从视野边上再来一个。三成的人会在视野里的某个门口停一两秒，脸朝着店。
- 点一个行人，他转过脸来看一眼，过一秒多接着走。不进店，不说话。
- 只在 `StreetScene.update` 里走，街不在眼前、窗口藏起来时一步都不动。小时数跟着店里显示的时辰走。钟上的点和店里的天色对得上，就用钟上的点。对不上的时候（调试、截图）取那段时辰中间的点，所以夜里截图街上是空的。
- 十个行人用人物生成器拼，跟店员、客人、玩家可选的样子都不重复，只留站和走两行。下雨下雪每人头上一把伞，用的是 D6 给出门跑腿的人画的那把，没有新画（Q-F10）。
- 场景 `street` 加一段。白天视野里一到五个人，点一个会转脸。切到夜里，人走完就没人再来。下雨时视野里一到两个人，走得快，人人有伞。三张图中英文都看过。

### F4 面包师和邮差的故事

**现状：** 三位讲故事的人，各 5 章（`app/shared/stories.ts:9-18`），`tests/stories.test.ts:23` 写死了只有三位。每章留一件东西在街上（`scripts/art/story.py`）。

**设计：**

- `TELLERS` 加 `baker` 和 `postman`，各 5 章，解锁照现在的办法：做满多少单，再隔几天。两人的单数错开，也和原来三位错开。
- 面包师讲他为什么在这条街上开面包房，邮差讲他送了二十年信记住的事。两条线在第 5 章碰一次头。
- 每章留一件东西，放在他们自己的店里，不放在街上。
- 先写样章：面包师第 1 章，中英文，放进 PR 说明给 Lewis 看。

**完成标准：** `tests/stories.test.ts` 改成五位讲的人，各章的解锁数对得上，中英文的键一样。场景 `stories` 加一段：两位新讲的人各读一章。

**做法：**

- `TELLERS` 加了 `baker` 和 `postman`，讲故事的还是客人桂姨和阿信。桂姨的五章在做满 6、16、26、42、54 单时来，阿信的在 10、20、32、45、57 单。两人不撞，也不跟原来三位撞。隔几天照旧是 0、3、4、5、7。
- 两人在自家门口等着讲，头上一样有气泡，点开是同一种故事卡。留下的东西挂在自己店里的墙上。面包房有三件在烤炉上方，邮局有一件在软木板旁边。其余的挂在第二扇窗和黑板之间，还有后门右边。都避开挂钟和店里长出来的东西，人走不到。十件都用 `scripts/art/tales.py` 手画，每件一张整屋大小的图。
- 桂姨讲她为什么在这条街开面包房：父亲的面包模子，父亲养下的老面，坐错车在街口下来，头一年的赊账本。阿信讲二十年送信记住的事：断了背带的旧邮包，给陈婆婆送的信，只写“亮着灯的店”的信，下大雪那年。两条线在第 5 章碰头：桂姨开张那天收的头一封信是阿信送的，桂姨忘了，阿信记得，信是她老家寄来的。阿信的第 2 章接上陈婆婆在长椅上等信，第 4 章里陈婆婆和桂姨都出场。
- 明信片只带街上三位的故事。两人的东西在店里，逛别人的店时看不到店里，也就不用带；旧版本收到新明信片也照样能开。
- 场景 `stories`：原来那一个月只看街上三位，桂姨和阿信在门口一直等着。月底再开一次店，两人各讲第 1 章，卡片对得上，进各自的店看墙上挂着第 1 章的东西，第 2 章的还没有。

### F5 新的台词

**现状：** 三间小店各约 143 行台词，闲聊 1,041 行（`lines/*.yaml`）。台词规则在 `app/renderer/translator/lines.ts`。

**设计：**

- `lines/bakery.yaml`、`lines/post.yaml` 各约 150 行，照小店的样子分组：开门、关门、天气、季节、客人来、做委托时。
- 闲聊加约 300 行：主店的人说起街上的新店、路过的人，面包师和邮差来店里时说的。
- 英文同量，不是逐字翻译，照英文的写作规则写。
- 先写样章：每个文件先写 30 行给 Lewis 看。

**完成标准：** `tests/lines.test.ts` 管住新文件，`npm run content` 数得到新增的行数。场景里截图看得到新台词出现。

**做法：**

- 开工时发现，F1、F2 为了让店能接活，已经把做委托时的那一套台词写齐了，每间约 143 行。街上的小店原来也没有闲聊：主店的闲聊只在主店里跑。所以这一包先补了一个小机制，再写台词。
- 机制在 `app/renderer/stage/shoptalk.ts`。走进一间街上的店，店主说一句 `shop_in` 里的话。有节日先挑节日的，再看天气，都没有就在时辰、季节和平常的里面随便挑。店里没活时，店主隔四十五秒到一分半说一句 `shop_idle`。先说合当下天气、季节、时辰的，再说平常的，说完一轮才重复。有活时不说，深夜多了收摊的话。
- 面包房和邮局各写了 24 句进门的话、46 句空闲时的话，中英文同一套 id。开门、关门、天气、季节都有，客人来过的事放在空闲的话里。两个文件各从 146 行长到 223 行左右。印刷铺、画室、工坊还没有这两组，店主照旧不说，以后补上就会开口。
- 主店的闲聊加了 84 段、272 句。主店的人聊面包房和邮局，聊街上走过的人，也聊两人讲过的故事和新来的四位客人。桂姨和阿信来店里时各多了十段。有下雨、下雪、花瓣、落叶、节日和等活时的。英文同样 84 段，照英文的规则另写，不逐字翻。
- 新闲聊让两条旧测试写死的期望变了：下雨天先聊的那几段，和阿信下雨来时说的那段。改成从台词里算，不再写死 id。
- 场景 `bakery` 和 `post` 加一段：走进店时店主说的是 `shop_in` 里的一句，截图中英文都看过。
