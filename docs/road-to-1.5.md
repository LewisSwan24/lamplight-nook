# 小灯屋 1.1 至 1.5 路线

基线：`main` 的 `0015c3a`（2026-11-14），也就是 1.0.0 发布之后。

这份文档定的是 1.0 之后五个版本的主线和工作包。每个版本的规模都按 0.5 到 1.0 来算：大约十来个工作包，最后过一道完整的发布关卡。方向是 Lewis 2026-11-14 定的，说的是“可以，细化”。

每个版本开工前，先把工作包再细化成一份单独的文档，1.1 的是 `docs/road-to-1.1.md`。写法照 `docs/road-to-1.0.md`：现状核查、每个工作包的设计和完成标准、待决定的事、发布关卡。这里只写到工作包这一层。

## 1. 五个版本

| 版本 | 主线 | 一句话 | 最大的风险 |
|---|---|---|---|
| 1.1 | 开门营业 | 能交给真实用户长期用 | 签名、商店审核和 Mac 都依赖外部条件 |
| 1.2 | 工作室 | 从一单一单变成长期项目 | 项目越大，每轮带给 Claude 的上下文越贵 |
| 1.3 | 接上真实世界 | 能做 Office 文件，能连上你的工具 | 外部动作出错的代价高，安全规则要重写 |
| 1.4 | 小镇 | 从一间店变成一条街 | 美术量最大，可能要请画师 |
| 1.5 | 和别人一起 | 分享、串门、手机和小团队 | 要有服务器，和现在纯本地的做法相反 |

排序的理由：

- 1.1 先让东西稳定地交到用户手里，后面几版的取舍才有真实使用的数据可看。
- 1.2 加深核心玩法。项目、并行和后台跑是 1.3 和 1.4 的地基。
- 1.3 扩大能做的事。1.4 把这些新能力变成街上看得见的店。
- 1.5 需要服务器，改变的是整个产品的隐私承诺，所以放在最后，也最晚定。

## 2. 每个版本的做法

沿用 1.0 的流程（`docs/road-to-1.0.md` 第 2 节），有三处调整：

1. **集成分支按版本开。** 1.1 用 `release-1.1`，发布时压成一个提交合进 `main`，和 1.0 的 D4 一样。
2. **CHANGELOG 按版本记。** 写在 “Unreleased (1.x)” 下面。
3. **版本之间可以重叠设计，不重叠实现。** 上一版还在发布关卡时，下一版可以先出设计稿，代码要等上一版发了再写。

固定规则不变：先定设计再写代码，先写会失败的测试，花钱、推送、开 PR、合并、打标签、删除都等 Lewis 说了才做。真实运行用装好的小灯屋里存的 Key，跑之前先报预算。

| A4 | 本地使用统计 | 无 | M | 否 | 否 |

**A1 签名和自动更新。** 安装包做代码签名，SmartScreen 不再拦。加自动更新，从 GitHub Releases 检查新版本。有新版本时邮差送来一封信，点开能看更新了什么，由用户决定什么时候装。更新失败要能退回旧版，数据不丢。

**A2 微软商店上架。** MSIX 真装一遍。1.0 时 Windows 拒绝安装，报 `0x80073D2B`，要查清原因。商店版的数据放在虚拟化的 AppData 里，要确认从安装包版换到商店版时作品和账本都在。然后在 Partner Center 提交，按审核意见改到通过为止。

**A3 真机账目和遗留验证。** 1.0 发布关卡里没勾的都在这里补：花费和 Anthropic Console 对账，预算卡的两个按钮真点一次，声音、讲述人和缩放逐项记录。再把每周的真实回归重新跑起来。

**A4 本地使用统计。** 只存在本机，不上传。记的是排队等跑腿的次数、每单用时、每单花费和失败类型。笔记本里加一页给用户看，用户可以一键清空。A5 要用这份数据决定学徒怎么做。

**A5 学徒。** 第五个店员，有自己的美术、走路和台词。Lewis 2026-11-04 定的是 1.0 后再加，先看排队数据。两种做法：只接跑腿活的表演角色，或者对应一个真帮手（比如专门跑检查的子代理）。后一种每单多花钱，要用真 Key 测过花费再定。

**A6 在已有文件夹里接着干。** 现在每单都新开一个文件夹。改成可以选一个已有的文件夹，比如你自己的网站或文档目录，店员在里面改。动手前先存一份改动前的版本，可以整单撤回。大文件夹只看和委托有关的部分，要有上限。

**A7 新委托模板。** 现在有八种。再加四种左右，候选：简历、读书笔记、旅行攻略、小工具脚本。模板改成数据驱动，加一种模板不用改代码。每种新模板都要用真 Key 跑一单看效果。

**A8 作品导出和分享。** 作品能打包成一个压缩包，网页类作品能导出成 PDF，能一键复制到指定位置。分享只是生成文件，不经过任何服务器。

**A9 第 20 单之后的成长。** 现在第 20 单之后就没有新东西了。把成长线延长到 100 单左右：季节变化、节日布置、新摆设、街坊的新话题。用了半年的人还要有新发现。

**A10 macOS 版。** 打包、签名、公证，菜单栏代替托盘，钥匙串存 Key，找到或引导安装 Mac 上的 Claude Code。没有 Mac 真机就不做，这一项挪到下一版。

**A11 1.0 的遗留问题。** 生日那句话会被错过、数据出问题的卡片显示旧预算，这两个已经修在分支 `fix-birthday-and-budget`。另外是 1.0 审查留下的三条：只给测试用的 `.js` 分支、`types.ts` 里过时的注释、`path.ts` 里重复的比较函数。

**A12 发布关卡和真机验证。** 全量验收中英文都过，真机装一遍安装包和商店版，真 Key 跑一轮完整委托，自动更新从 1.0.0 升到 1.1 实测一次。

## 4. 1.2 工作室

目标：用户可以把一件大事交给小店做上几个星期，比如一个网站、一本小册子或一套表格。店员记得来龙去脉，用户不用守在电脑前。

细化见 `docs/road-to-1.2.md`，在 `release-1.1` 上接着做，1.1 的 A10 macOS 版也挪到了那里。

| 编号 | 内容 | 依赖 | 改动量 | 新美术 | 真 Key |
|---|---|---|---|---|---|
| B1 | 项目模型和数据迁移 | 1.1 | L | 否 | 否 |
| B2 | 项目板和时间线 | B1 | L | 是 | 否 |
| B3 | 项目记忆 | B1 | M | 否 | 是 |
| B4 | 先商量再动手 | 无 | L | 少量 | 是 |
| B5 | 多单并行 | B1 | L | 否 | 是 |
| B6 | 后台跑和定时委托 | B5 | L | 否 | 是 |
| B7 | 中断和跨天恢复 | B5、B6 | M | 否 | 是 |
| B8 | 项目和每月的预算 | B1 | M | 否 | 否 |
| B9 | 并行时店里的表演 | B5 | L | 是 | 否 |
| B10 | 发布关卡和真机验证 | 全部 | M | 否 | 是 |

**B1 项目模型。** 一个项目是一个文件夹加上它的所有委托、版本和备忘。1.1 以前的每件作品迁成只有一单的项目，老用户打开后什么都不少。

**B2 项目板。** 店里加一块看板，每个项目一张卡。点开是项目的时间线：每一轮做了什么、花了多少、哪一版。可以退回到任何一版，也可以从某一版岔出去重做。

**B3 项目记忆。** 每轮开工时带给 Claude 的项目背景：项目是干什么的、用户定过的偏好、上一轮做到哪里。用户能看能改。项目越大带的越多，要量过每轮多花多少钱，并设上限。

**B4 先商量再动手。** 开工前先和阿灯聊几句，把要什么说清楚，最后生成一张委托单。聊天用便宜的模型，花费单独记账。商量好才开始花大钱。

**B5 多单并行。** 几单可以同时跑，店员分组干活。所有并行的单共用一个总上限，排队规则写清楚。

**B6 后台跑和定时委托。** 小店最小化或关到托盘时继续干活，做完发系统通知。可以排定时委托，比如每周一早上整理一份周报。开机自启默认关闭。

**B7 中断和跨天恢复。** 长项目中途断网、睡眠、关机，下次打开能接着做，不重复花钱。1.0 已经能接着做一单，这里扩展到并行和定时的情况。

**B8 项目和每月的预算。** 除了每轮上限，加上每个项目的上限和每月的总上限，快到时提前提醒。

**B9 并行时店里的表演。** 两三组人同时干活时，谁在哪里、谁和谁开会，要看得懂，也不能挤成一团。看板前可以开项目会。

**B10 发布关卡和真机验证。** 用真 Key 跑一个至少五轮的项目，中间关机一次，再跑一个定时委托。

## 5. 1.3 接上真实世界

目标：小店做的东西能直接拿去用，Word、Excel、PPT、PDF 都能做。也能在用户同意下连上邮箱、日历和网盘。

| 编号 | 内容 | 依赖 | 改动量 | 新美术 | 真 Key |
|---|---|---|---|---|---|
| C1 | Office 和 PDF 的读写 | 无 | L | 否 | 是 |
| C2 | 图片和图表 | 无 | M | 否 | 是 |
| C3 | 改文档的模板放宽 | C1 | M | 否 | 是 |
| C4 | 连接框架 | 无 | L | 否 | 否 |
| C5 | 首批连接 | C4 | L | 少量 | 是 |
| C6 | 外部动作的安全规则 | C4 | M | 否 | 否 |
| C7 | 调研报告带出处 | 无 | M | 否 | 是 |
| C8 | 资料室和邮局 | C1、C5 | L | 是 | 否 |
| C9 | 发布关卡和商店政策复核 | 全部 | M | 否 | 是 |

**C1 Office 和 PDF。** 能做出 docx、xlsx、pptx 和 PDF，结果卡里能预览。递过来的这几种文件也能读。

**C2 图片和图表。** 能看懂递过来的照片，能做图表、海报这类用网页画出来再存成图片的东西。接不接图像生成模型由 Lewis 定，接的话要另一家服务的 Key。

**C3 改文档的模板放宽。** 现在只收 txt、md、html、csv、json，1MB 以内。放宽到 Office 和 PDF，上限也提高。原文件照旧不动，只改复制件。

**C4 连接框架。** 通过 MCP 连外部工具。每种连接一张授权卡，写清能读什么、能做什么、怎么断开。现在 `mcpServers` 是空的，权限规则也只管本地文件，要整体扩展。

**C5 首批连接。** 挑两三种做透，候选是邮箱、日历和网盘。邮箱先只起草，不直接发送。

**C6 外部动作的安全规则。** 发邮件、改日历、删网盘文件这类做了收不回的事，一律先问用户。每次外部动作留记录，用户随时能查。

**C7 调研报告带出处。** 现在已经能查资料写总结。改成每条结论都附出处，结果卡里能点开核对，查不到出处的要标明。

**C8 资料室和邮局。** 店里加地方让新能力演出来：做 Office 文件的人去资料室，连接邮箱和日历时邮差进出。

**C9 发布关卡。** 用真 Key 每种新格式和每种连接各跑一单。再按微软商店对生成式 AI 的政策复核一遍，1.0 时参照的是 11.16 条。

## 6. 1.4 小镇

目标：小店长成一条街。每间店专做一类活，委托交给哪间店，就在哪间店里演。小镇随作品一起长大。

| 编号 | 内容 | 依赖 | 改动量 | 新美术 | 真 Key |
|---|---|---|---|---|---|
| D1 | 街道和多场景切换 | 1.3 | L | 是 | 否 |
| D2 | 三间新店 | D1 | L | 是 | 否 |
| D3 | 派单到店 | D2 | M | 否 | 是 |
| D4 | 街坊的故事线 | D1 | L | 是 | 否 |
| D5 | 小镇随作品成长 | D1 | L | 是 | 否 |
| D6 | 全街的季节和节日 | D5 | M | 是 | 否 |
| D7 | 老店升级成小镇 | D1 | M | 少量 | 否 |
| D8 | 性能和低配机 | D2 | M | 否 | 否 |
| D9 | 美术的来源和授权 | 无 | M | 是 | 否 |
| D10 | 发布关卡和真机验证 | 全部 | M | 否 | 是 |

**D1 街道。** 加一个街道场景，店员和用户能从一间店走到另一间店。现在的咖啡馆和书房变成街上的两个门面。

**D2 三间新店。** 候选是印刷铺（文档）、画室（图片）和工坊（程序和小工具）。每间有自己的内景、家具层和寻路，至少一个新店员。

**D3 派单到店。** 委托按类型交给对应的店。一单跨几种活时，店员之间送东西、跑腿，表演跟着真实的子任务走。

**D4 街坊的故事线。** 老周、陈婆婆、小禾各有一条好几章的故事，按作品数和日子往前走。1.0 的街坊只有零散的台词。

**D5 小镇成长。** 作品越多，街上长出越多东西：新门面、路灯、集市、小公园。

**D6 全街的季节和节日。** 1.1 的节日从一间店扩到整条街。

**D7 老店升级成小镇。** 老用户第一次打开 1.4 时，要演一段小店搬上街的过程，原来的摆设、作品和成长都留着。

**D8 性能。** 角色和物件会多出好几倍，要在低配机上量过帧率和内存，定出上限。

**D9 美术。** 按 1.0 的 D1，先用现有素材包拼，不够再请人画。LimeZu 素材的授权要在这时问清楚，1.0 的 D8 没有问。

**D10 发布关卡。** 全量验收，旧数据升级实测，低配机实测，真 Key 跑一单跨几间店的委托。

## 7. 1.5 和别人一起

目标：作品能分享给别人，能去朋友的小店串门。出门时用手机看进度和批准请求，一家人或一个小团队可以共用一间店。

这一版需要服务器。小灯屋到 1.4 为止都只在本机运行，除了 Anthropic 的接口什么都不连。所以 E0 不定，后面都不开工。

| 编号 | 内容 | 依赖 | 改动量 | 新美术 | 真 Key |
|---|---|---|---|---|---|
| E0 | 服务器和隐私的总决定 | 无 | S | 否 | 否 |
| E1 | 账户和服务端 | E0 | L | 否 | 否 |
| E2 | 分享作品 | E1 | L | 否 | 否 |
| E3 | 去朋友的小店串门 | E1 | L | 是 | 否 |
| E4 | 手机端 | E1 | L | 是 | 否 |
| E5 | 小团队共用一间店 | E1 | L | 少量 | 是 |
| E6 | 内容安全和举报 | E2、E3 | M | 否 | 否 |
| E7 | 运维：成本、监控、备份 | E1 | M | 否 | 否 |
| E8 | 发布关卡 | 全部 | M | 否 | 是 |

**E0 总决定。** 服务器由谁托管、存什么不存什么、隐私政策怎么写、用户的 Key 和作品内容会不会离开本机。这一项只出方案，由 Lewis 定。

**E1 账户和服务端。** 最小的账户系统，只存分享和串门需要的东西。能用端到端加密的地方都用上。

**E2 分享作品。** 生成一个链接，朋友不装小灯屋也能在浏览器里看。分享可以随时撤回。

**E3 串门。** 去朋友的小店看看摆设和成长。作品内容只有对方分享过才看得到。

**E4 手机端。** 看进度、收通知、批准授权请求。形式是网页应用还是原生应用，在 E0 一起定。

**E5 小团队共用一间店。** 几个人用同一间店，各自的委托和花费分开记，有人能批准，有人只能看。
