# 小灯屋 2.0 小镇的一年

2026-11-28 写，照 `docs/road-to-2.0.md` 第 8 节细化，并且加重。1.9.0 当天从 `main` 的 `55171bf` 发布，Lewis 说「制定2.0重型大规模迭代计划和工作流」。

## 1. 目标

2.0 把前面五版加的东西串成一年。第一条街走到头，过一座桥，是一条沿河的街。河边开着花店和书店，两位新店主各有自己的故事。河边立着一座停了很多年的老钟楼，全镇用一年把钟楼修好，每个月一章，讲的人轮流。河水跟着天气和季节变，端午、元宵、中秋在河上过。最后有一本镇志，看过的故事、长出来的东西、过过的节日、收到的明信片，都收在里面，能重看。

路线图给 2.0 排了 7 个包。这份计划拆成 12 个，分四个阶段做。多出来的是河上的日子、钟楼本身、两条街之间的走动，还有一个只管老数据的包。

新加的台词大约这么多，英文同量：

|---|---|
| J2 两位店主在店里说的话 | 约 60 |
| J3 两位新街坊各讲 5 章 | 约 50 |
| J4 两种新委托的店里话 | 约 20 |
| J5 河上的日子和河上的节日 | 约 50 |
| J6 钟楼 | 约 20 |

| J9 两条街的闲聊和招呼 | 约 180 |
| 合计 | 约 510 |

1.9 加了约 390 句，2.0 多三成。

## 2. 流程

照 `docs/road-to-2.0.md` 第 9 节，再加 1.8 和 1.9 做下来学到的。

### 2.1 分支和合并

1. `release-2.0` 从 `main` 的 `55171bf` 开，跟 1.9.0 发布的是同一棵树。本计划先合进去。
2. 每个包一条分支，名字带编号，比如 `j1-river-street`。做完开 PR，压成一个提交合进 `release-2.0`。
3. 版本号、标签、合进 `main`，都等 Lewis 说。标签由 Lewis 自己打。

### 2.2 四个阶段

| 阶段 | 包 | 做完以后 |
|---|---|---|
| 一 新街新店 | J0、J1、J2、J3、J4 | 能走到河边，进得了花店和书店，听得到两位店主的故事，递得了两种新单 |
| 二 街上的日子 | J5、J6、J9 | 河会变，钟楼立起来，两条街的人来回走 |
| 三 一年 | J7、J8 | 主线 12 章讲得完，镇志里什么都有 |
| 四 收尾 | J10、J11 | 老数据升得上来，发布关卡全过 |

每个阶段做完有一道阶段关：

- 跑这个阶段改到的场景，再加冒烟的 `demo`、`street`、`shops`，中英文都过。
- 类型检查，加上这个阶段改到的单元测试。
- 截图放进 `sim-out/review-2.0/<阶段>/`，写一段短中文给 Lewis：做了什么，哪里要他看一眼。
- 不等 Lewis 回复，接着做下一阶段。Lewis 说要改，就插在下一个包前面改。

### 2.3 每个包

1. **先写会失败的测试。** 代码先写测试，看着测试失败，失败的原因要是少了这个功能，写错字不算。内容也一样，先在清点脚本里写上要有的数，看着清点报缺。
2. **样章先行。** 要加五十句以上台词或者一段故事的包，先写一章或三十句，中英文都写，放进 PR 说明里。不等回复，接着写完。
3. **台词守写作规则。** 中文每个气泡不超过 20 个字，最多一个语气词，不写情绪词。英文每个气泡不超过 44 个字符，最多一个感叹号。老石不用语气词，也不用感叹号。`tests/lines.test.ts` 管着，中文文档过 `zh-prose-check`。
4. **台词用脚本生成。** 每个包的台词写在草稿目录的生成脚本里，再由脚本写进 `lines/*.yaml` 和 `lines/en/*.yaml`。新台词的编号带包的前缀，测试按前缀数，不按人名数。1.9 数人名时撞上了“邮票”和“朱砂”这样的普通词。
5. **美术走脚本。** 每张新图由 `scripts/art/` 里的脚本从素材包拼出来，或者在脚本里手画，写进 `docs/art-2.0.md`，`tests/art-sources.test.ts` 查。图本身不进仓库，发布前导到私有素材库。
6. **只跑相关的检查。** 跑改到的单元测试和场景，中英文截图都看。一个包改了某种委托由谁做、在哪做，用到这种委托的老场景也要重跑。1.9 才发现 `apprentice` 从 1.4 起就坏了。
7. **文件格式。** 文件用 CRLF，`tools/sim/*.mjs` 和 `scripts/*.mjs` 用 LF。改代码不用 `sed -i`，用 Python 改并且保住换行。改 `locales/*.json` 用脚本读写，不手拼。
8. **文档照旧。** 改本计划的做法和状态，加一行进度记录，CHANGELOG 写在 “Unreleased (2.0)” 下面，`npm run content` 更新 `docs/content.md`。

### 2.4 真 Key

- 开跑前用一句中文报预算，Lewis 说可以再跑。
- 用当前分支的构建打开真实的数据文件夹，让应用自己解开自己存的 Key。不解密、不复制、不打印 Key。
- 跑之前先把 `%APPDATA%/Lamplight Nook` 备份到 `C:/Users/LewisDong/Backups/`。
- 跑完报花了多少，问 Lewis 要不要清掉试跑留下的作品。

### 2.5 节奏和额度

- **一次做一个包。** 大规模指的是一个包接一个包往深里做，不是同时开很多会话。
- **旁支会话最多一个。** 只给不碰同一批文件的美术脚本用，而且要 Lewis 说。后台任务和助手合起来不超过十个。
- **每个包开工前看一眼额度。** 一周的额度用得比时间快 10 个点以上，就只做不花钱、不用判断的包，不跑可选的检查。
- **长的包记进度。** 超过三十步的包，在会话的草稿目录里留一份 `progress.md`，上下文被压缩以后照着接上。

### 2.6 发布

照 1.8.0 和 1.9.0 的做法：

1. 全量单元测试挡住 playwright 跑一遍，看退出码。办法是把用户目录下 `node_modules` 里的 `playwright` 和 `playwright-core` 临时改名，先确认 `require('playwright')` 找不到，跑完改回来。
2. 用 `scripts/pack-assets.mjs` 先比一遍私有素材库的差异，看过再导，再在私有库里提交推上去。
3. 版本号在 `release-2.0` 上改成 2.0.0，写 CHANGELOG 和 `release-notes/v2.0.0.md`。
4. `release-2.0` 压成一个提交合进 `main`，Lewis 自己打标签，标签推上去就会发布。
5. 发布跑完，看一遍发布页：安装包、blockmap、`latest.yml`、msix 都在，说明跟文件一致。

## 4. 工作包

### J0 地基

**现状**

- 店的编号是 `app/shared/town.ts:5` 的 `ShopId`，七个，排在一条街上。能进的房间是 `app/shared/scenes.ts:16` 的 `ROOMS`。
- 街的样子来自 `assets/sprites/town.json`，由美术脚本生成，`app/renderer/game/town.ts:17` 读进来。只有一条街。
- 数据版本是 `app/main/migrate.ts:23` 的 `DATA_VERSION = 5`。
- `tests/fixtures/userdata/` 只有 0.5.0、0.6.1、0.7.0 三份老数据。1.0.0 以后的数据没有样本。

**设计**

- `ShopId` 加 `florist` 和 `bookshop`，`ROOMS` 跟着加。每间店记一个 `street`，`main` 或 `river`。
- 街的数据分成两条，每条有自己的宽度、店面和门。现在用到 `TOWN` 和 `FRONTS` 的地方，改成先问在哪条街。
- 数据版本升到 6。新的东西放进 `TownDays`：主线讲到第几章、钟楼修到哪、镇志看过什么。升级只加空的字段，不改老的。
- 补两份老数据样本：一份 1.0.0 的，一份 1.9.0 的，从脚本生成，不从 Lewis 的真实数据拷。

**完成标准**

- 单元测试：五份老数据都能升上来，作品、长出来的东西、故事、明信片一样不少。
- 只有一条街的时候，现有场景 `street`、`shops` 中英文照旧过。

**做法（做的时候改的）**

- **数据版本不升。** 1.9 加店员的故事时，新东西放进可选的字段，老数据没有就当空的，不用改老数据的样子。2.0 也照这样。河边街开张那一下，照 1.4 搬上街的办法记一个记号：新开的店一开始就记上，老店没有，打开时演一次。真要改老数据的样子再升版本，到时候写进那个包。
- **店的编号。** `app/shared/town.ts` 加了 `STREETS`（`main`、`river`）和 `SHOP_STREET`，`ShopId` 从这张表来。花店和书店在河边街，花店离桥近。`ROOMS` 先不加，J2 开门时再加，不然会去载还没有的图。
- **街的数据没拆。** 河边街的样子要等 J1 的 `river.py` 画出来才知道，现在拆只能猜。J1 再拆。
- **店名和门口的话。** 两种语言都加了花店和书店的名字，门口那句先写“还在装修，过些日子开张”。
- **老数据样本。** `tools/sim/legacy.mjs` 加了 `--chain 1.0.0,1.9.0`，模拟一位从 1.0.0 用起的用户。先用 1.0.0 做一个网页、改一轮、查一次资料，升到 1.9.0 再查一次资料、做一个网页，最后升到现在的版本。两个旧版本各开一个工作区构建，1.9.0 要先导入私有素材库的图。样本里的家目录换成 `{HOME}`，原来的写法漏了 JSON 里双写的反斜杠，顺手改了。
- **测试。** `tests/streets.test.ts` 4 个，`tests/migrate.test.ts` 加 2 个：1.0.0 的数据从版本 3 升到 5，作品、单数、长出来的东西都在；1.9.0 的数据不用升，小橘做过的单子也数得到。先把样本挪开，看着这两个失败，再放回来。

### J1 河边街

**现状**

- 走出店门是 `StreetScene`，左右走，镜头跟着人。街的尽头没有路。
- 素材包里有水的地块、码头的木桥（`Pier_Bridge`）、长椅、路灯、花丛。学校的钟楼只有会转的指针（`School_Clock_Tower_Hand_*`），没有塔身。

**设计**

- 第一条街的右头加一座桥。走过桥，镜头换到河边街。河边街是一条新的长条，上半是街，下半是河。
- 河边街从左到右：桥头、花店、钟楼的旧架子、书店、一段河岸。两间新店先只有门面，进门在 J2。
- 钟楼的旧架子先画一个停了的样子，修起来在 J6。
- 新图写进 `docs/art-2.0.md`。河边街的底图、两间店面、旧钟楼，都由 `scripts/art/` 里新的 `river.py` 生成。

**完成标准**

- 新场景 `riverstreet`：从家走到河边街再走回来，中英文都过，截图看过。
- 帧率用 `tools/sim/fps.mjs` 量一次河边街，不比第一条街低。

**做法（做的时候改的）**

- **一条街接着走，镜头不换。** 河边街接在第一条街的右头，同一个场景，拖着走或者按方向键就过了桥。路人、天气、夜里变暗都不用另做一份，桥那一段算第一条街。整个镇从 1128 像素宽变成 1912 像素。
- **图。** `scripts/art/river.py` 借 `town.py` 的素材和尺寸，画出地面、两间门面、摆设、钟楼四张图和 `river.json`，`app/renderer/game/town.ts` 把位置往右挪 1128 接上。花店用红砖楼，窗上有条纹遮阳篷，门口三桶花。书店用灰石楼，一扇拱形大窗。钟楼手画：灰石塔身，钟面没有指针还裂了一道，屋顶塌了一半，门用木条钉着。第一条街的路过了桥到头，后面是河。
- **两间店还不能进。** 点门面说“还在装修，过些日子开张”，点钟楼没反应。进门在 J2。
- **修了路人的一个老毛病。** 往右走的路人从画面左边外面出发，在街的最左头，出发点在镇子外面，一出来就被当成走出了镇子删掉。所以站在咖啡馆门口时，路人只会从右边来。白天街上一开始就站满了人，看不出来。半夜跑场景时一开始一个人都没有，运气差就一直没人，J0 记下的 `street` 时过时不过就是这个。现在走出镇子两头再远一点才删，单元测试先复现了这个毛病。场景里切到白天以后，也多等几秒让第一个人走进来。
- **测试。** `tests/river.test.ts` 8 个，`tests/crowd.test.ts` 加 1 个，`tests/town.test.ts` 的七间门面改成九间，`tests/art-sources.test.ts` 读新的 `docs/art-2.0.md`。新场景 `riverstreet`：方向键一路走到河岸尽头，点两间店和钟楼，桥上、夜里、雨里各截一张，再走回咖啡馆进门。
- **帧率。** 4 倍降速量了两次，每处 60 秒。第一次河边街 24.9 帧、第一条街 27.3 帧，可河边街每帧画得更快（中位 2.3 毫秒，第一条街 2.4）。第二次河边街 27.2 帧、第一条街 25.9 帧，这回是家里掉到 23.1 帧。掉帧的地方两次不一样，算机器抖动，河边街不比第一条街慢。
- **没做的，留给 J5。** 河边街还没有季节和节日的装饰，冬天也不积雪，水是静的。

### J2 花店和书店

**现状**

- 面包房、邮局、画室都是 1.4 以后加的能进的店，有店主、会长的东西（`app/shared/towngrow.ts:32` 的 `ROOM_GROWTH`）和店里话（`shop_idle`）。新店照这个做。
- 素材包里有成套的图书馆家具（`5_Classroom_and_library`）和花园里的花和花瓶（`17_Garden`）。

**设计**

- 两间店各一个房间，各一位店主，名字见 Q-J1。店主的样子从人物生成器拼，写进 `characters.py`。
- 屋里会长的东西各 6 样，跟着这间店做过的单子长，跟面包房一样。
- 店主各说约 30 句店里话，带季节、天气、钟点。
- 店主跟着天亮开门、天黑关门，跟别的店一样。

**完成标准**

- 新场景 `florist`、`bookshop`：进门、店主说话、点会长的东西，中英文都过，截图看过。
- 老场景 `shops` 重跑，中英文都过。

**做法（做的时候改的）**

- **花店的编号叫 `flowershop`。** `florist` 已经是客人芳姐的编号，客人的行走图就叫 `florist.png`，画花店时被盖掉过一次，已经重画回来。J0、J1 里用到花店编号的地方都改了。
- **花店是芳姐的店，书店是简伯的。** 芳姐在店里的闲聊里本来就卖花，再来一个芸姐，小镇上就有两个卖花的。照 1.6 面包师变成桂姨的办法，客人芳姐当店主，英文还叫 Fern。书店店主叫简伯，英文 Uncle Page，因为老周已经是修车的那位客人。
- **会长的东西和店主算单数，挪到 J4。** 这两样都按接派单的店来算，阿登要到 J4 才往这两间店派单。在这两间店的柜台递委托，现在还是回家里做。
- **不做开门关门。** 别的店也没有，门一直开着。
- **图。** `scripts/art/flowershop.py`、`bookshop.py` 画两间内景，用咖啡馆的格局。花店有花桶、花台、小盆栽架和包花桌，书店有大书架、看书的长桌和地球仪。两张桌子底下加了一条横板，看着是实的，拆家具的测试也靠这个认出桌子。`pieces.py` 拆家具，`portraits.py` 加了两位店主的头像，简伯戴眼镜。`docs/art-2.0.md` 记了 8 张图。
- **节日装饰先用咖啡馆的。** 街上五间店的节日装饰各有一格，两间新店还没有，`pieces.py` 只给那五间换装饰，这两间用咖啡馆的。新店的装饰放到 J5，跟河边街的一起画。
- **规则和台词。** 两间店的规则照邮局的抄，换上店主。台词由草稿目录里的脚本生成，每位店主 153 句。干活时的每一组都有，不然咖啡馆的人会在花店里说话。进门打招呼 29 句，带钟点、天气、季节，每个节日一句。店里闲聊 32 句。编号前缀是 `fl_` 和 `bs_`。家里的生日那组加了两句，阿登提醒大家给两位店主过生日。
- **两个字的坑。** 手写字体里没有“扉”字，台词里改成“头一页”。英文的情绪词检查不分大小写，“Happy New Year”过不了，改成“A good New Year to you”。
- **“店主的店”和“会长东西的店”分开。** 原来只有一个 `isStreetShop`，按会长的东西那张表算。河边两间店不在表上，场景跑出来店主进门不说话，干活的也成了阿登。现在 `app/shared/scenes.ts` 加了 `isKeptRoom`，家里两间以外都算店主的店。打招呼、闲聊、谁来干活、卡片上写谁，看的是它。会长的东西和节日装饰还看 `isStreetShop`。
- **测试。** `tests/riverrooms.test.ts` 7 个。一个查两间店算店主的店，规则跑起来只有店主干活，家里只来阿登，递单就走。最后一个查两种语言的台词守写作规则、编号一一对上、只有店主说话。`tests/rooms.test.ts` 的新店表加了两间，那里对每间店的检查也就都管上了。列着店和店员的老测试跟着改，`tests/river.test.ts` 的两间店从关着改成开着。
- **场景。** 新场景 `rivershops`：从街上进花店、进书店，店主说进门那句，屋里只有店主，过一会儿书店里还是只有简伯。`riverstreet` 点门面改成进门，再走回街上。`bakery`、`post`、`shops` 重跑。
- **访客那边。** 去别人店里做客时，点花店、书店的门，跟面包房、邮局一样说门口那句。

### J3 两位新街坊

- 讲什么见 Q-J1。故事里跟老街坊有交集，比如书店老板跟小橘一样爱泡图书馆，花店的花是桂姨院子里分的苗。

**完成标准**

- 样章先行：每人先写第一章，中英文都写，放进 PR 说明。
- 老场景 `stories` 加上两位新店主，中英文都过。

**做法（做的时候改的）**

- **故事跟的是全店的单数。** 现状里写的“跟着自己店的单数走”不对，`nextChapter` 用的一直是全店做过的单数。所以两间店要到 J4 才接活，故事现在就能来。
- **简伯也成了街坊。** 讲故事的人得是街坊，芳姐本来就是（`florist`），简伯新加了一个 `bookseller`。行走图跟店主简伯同一套搭配，名字也一样。简伯来店里串门的话写了 7 段，三段平常的，四季各一段。可眼下没有哪种活会带简伯来，等 J4 书店的书单做了才来。

- **场景。** `stories` 最后一天，四位店主都在自己门口等。点开第一章，再进店看东西挂上了，河边两位也在里面。镜头能走到河边街了。

### J4 两种新委托

**现状**

- 委托种类有 26 种，在 `app/shared/templates.ts`。每种归一间店，由那间店的店主或者家里人做。
- 1.8 加七种新委托时，每种先用替身 Claude 跑通流程，再用真 Key 跑一单。

**设计**

- 花店接“插花卡片”：说清送给谁、什么场合，出一张卡片图，配一段写在卡上的话。
- 书店接“书单”：说清想读什么、读过什么，出一份带推荐理由的书单。
- 每种一句客人进门说的话，一个做完后长在店里的东西。

**完成标准**

- 替身 Claude 跑通两种，新场景 `floristorder`、`bookorder` 中英文都过。
- 真 Key 每种跑一单，约 $2。先报预算，Lewis 说可以再跑。

**做法（做的时候改的）**

- **两种新活。** 花店写花卡（`flowercard`），就是随花一起送的小卡片，交回一张 900×600 的图和一份 PDF。书店开书单（`booklist`），默认 8 本，最多 15 本，交回 Word 和 PDF。书单上每本书都让研究员查一遍，查不到就拿掉。
- **阿灯把单子送过河。** 两间店进了 `SHOPS`、送单的那条街和店主表，店主是芳姐和简伯。缺的工具照旧去别家借：PDF 去印刷铺，出图去画室。
- **每间店长四样，不是设计里的六样。** 跟老街上的店一样，在 1、3、8、20 单各长一样。花店是一盘小苗、绿萝、旧水壶、花篮；书店是第一张价目单、绿萝、石膏像、书梯。写过花卡，墙上多一个卡片架；开过书单，多一块钉书单的软木板。
- **J3 的纪念品挪了地方。** 墙上那三个格子是各店长东西的位置，J3 的纪念品有几样正挂在上面。现在挪到格子下面、后门右边和黑板旁边，`tests/stories.test.ts` 查过互不重叠。
- **门口和节日装饰留给 J5。** 河边街的门面还没画花盆、招牌和彩旗，所以“门口长了东西”的话先不说。过节时两间店先挂咖啡馆那套装饰。
- **明信片只带老街。** 明信片照旧只记五间老店的单数，跟 J3 只记三位老街坊的故事一个道理。这样 2.0 寄出的明信片，1.9 也打得开。
- **客人。** 书单把简伯带来串门。花卡不带新客人，芳姐早就由邮局的贺卡带来了。
- **测试。** 新加 `tests/riverwork.test.ts`：活归哪间店、谁做、店里长什么、借工具、门口和节日先不动。`tests/postcard.test.ts` 查明信片不带河边两间店。模板表、客人表、店里长东西的表都加上了两种新活。
- **场景。** 新场景 `floristorder` 和 `bookorder`：在家下单，阿灯送过河，店主在店里做好，墙上长出东西，回家阿灯说一句。书单那个最后还看简伯进门说话。
- **真 Key 跑过了，两单共 $0.73。** 花卡 $0.14、0.8 分钟：给楼下王阿姨的谢卡，在花店做，名字照写，右下角一枝粉花。书单 $0.59、2.5 分钟：给初一男孩的 8 本冒险和太空书，在书店做，分三段。研究员查了两轮，8 本的作者和年份都对得上。没有中文版的那本，书单上也注明了。
