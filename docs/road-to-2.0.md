# 小灯屋 1.6 至 2.0 路线

2026-11-25 起草，Lewis 的话：「制定1.6-2.0大规模重型迭代计划和工作流，重点在内容拓展方面」。

## 2. 开工前要先有的

1. **素材授权（Q-D3）。** 改过的整张图打进安装包算不算再分发，到今天还没问 LimeZu。1.4 起的版本都卡在这里。2.0 以前的美术会比现在多一倍，答案要是“不行”，返工的量也翻倍。所以 1.6 开工前先发信，信稿在 `docs/art-1.4.md:68`。
2. **1.5 发不发。** 建议 1.5 先发，`release-1.6` 从发了的 `release-1.5` 开。不发也能开工，但五个版本压在一起发，出了问题很难找。
3. **欠着的真 Key。** 1.1 到 1.5 欠的真 Key 单子加起来约 $50。建议每个版本的发布关卡顺手补一部分，2.0 以前补完。

| F3 | 街上的行人：按时辰和天气走动，下雨打伞 | M | 是 | 否 |

## 9. 工作流

### 9.1 每个版本

1. **集成分支按版本开。** 1.6 用 `release-1.6`，从上一版的发布分支开。发布时压成一个提交合进 `main`。
2. **先写本版计划，Lewis 点头再写代码。** 计划里每个包写现状（带行号）、设计、做法、完成标准。要定的事列成 Q 表，先按建议做，标**暂定**。
3. **版本之间可以重叠设计，不重叠实现。** 上一版在发布关卡时，下一版可以先写计划。
4. **一个包一个分支。** 名字带编号，比如 `f1-bakery`，做完开 PR 合进本版分支。

### 9.2 每个包

1. **先写会失败的测试。** 代码照旧。内容也一样：先在清点脚本里写上要有的数，看着它报缺，再写内容。
2. **样章先行。** 要加五十行以上台词或者一段故事的包，先写一章或三十行，中英文都写，放进 PR 的说明里给 Lewis 看。不等回复，接着写完。Lewis 说要改，就照改。
3. **台词守写作规则。** `tests/lines.test.ts` 管台词，`zh-prose-check` 管中文文档，都要过。
4. **美术走脚本。** 每张新图由 `scripts/art/` 里的脚本从素材包拼出来，写进美术清单，`tests/art-sources.test.ts` 查。新图进私有的素材仓库，由 Lewis 推。
5. **只跑相关的检查。** 跑改到的单元测试和场景，中英文截图都看。全量单元测试留给发布关卡，全量验收只在 Lewis 说的时候跑（2026-11-24）。
6. **文档照旧。** 本版计划的做法和做的时候改的，总览状态，进度记录一行，CHANGELOG 写在 “Unreleased (1.x)” 下面，`docs/content.md` 更新。

### 9.3 发布关卡

1. 类型检查和全量单元测试。
2. 本版新加的场景中英文全过，再加一组冒烟场景：`demo`、`lan`、`street`、`shops`。
3. 打包检查过，安装包比上一版大了多少记下来。内容多了，安装包会涨，每版涨超过 5 MB 要说明原因。
4. 低配电脑的帧率：每版用 `tools/sim/fps.mjs` 量一次，比 1.5 低了要说明。
5. 真 Key：先用一句中文问 Lewis 预算，他说可以再跑。用应用里存的 Key，先备份数据文件夹。
6. 版本号、标签、发布、合进 `main`，都等 Lewis 说发。

### 9.4 节奏和额度

- **一次做一个包。** 大规模指的是一版接一版往深里做，不是同时开很多个会话。需要并行时，一次最多一个旁支会话，而且只做不碰同一批文件的事。后台任务和助手合起来不超过十个。
- **每个包开工前看一眼额度。** 一周的额度用得比时间快 10 个点以上，就只做不花钱、不用判断的包，不开工作流，不跑可选的检查。
- **长的包记进度。** 超过三十步的包，在会话的草稿目录里留一份进度笔记，上下文被压缩以后照着接上。

## 10. 风险

| 风险 | 后果 | 怎么办 |
|---|---|---|
| LimeZu 说改过的图也不能打包 | 1.4 以后的美术都要换 | 1.6 开工前问清。不行的话，新图全改成脚本手画，量会大很多，到时候重排计划 |
| 素材包里的东西用完了 | 新店、新动物拼不出来 | 每版计划里先清点要用的素材，缺的写进 Q 表 |
| 台词多了，质量往下掉 | 店员说话变得像模板 | 样章先行，写作规则的测试管着，每版抽一百行给 Lewis 看 |
| 东西多了，低配电脑变慢 | 帧率掉 | 发布关卡量帧率，离屏的店照 D8 的省电办法停下来 |
| 两种语言的量翻倍 | 英文跟不上，或者译得生硬 | 中英文同一个包写完，清点脚本对键，英文照写作规则另外检查 |
| 新委托的提示词不稳 | 真 Key 跑出来的东西不对，花钱重跑 | 每种先用替身 Claude 把流程跑通，真 Key 一次只跑一单 |
