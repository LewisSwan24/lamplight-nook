# 小灯屋 1.0 上线前工作流

基线：`main` 的 `1a8ee39`（2026-11-04）。文中的 `路径:行号` 都对应这个提交，代码改动后行号会漂移。

这份文档是 1.0 之前的唯一工作清单。下面的工作包全部完成，并且通过第 7 节的发布关卡，才发 1.0。

## 1. 目标

让小灯屋从“能看的戏”变成“能摸、能看懂、讲得通的店”：

- **看得懂：** 委托进行到哪一步、用了多久、上限多少，一眼能查到。
- **讲得通：** 人站在合理的位置，走路不穿家具，能走到家具后面。
- **摸得着：** 看起来能点的东西，点了都有反应。
- **活起来：** 角色真的在做事，店里发生的事和你做过的委托有关。
- **找得到：** 菜单和入口有统一的结构。

## 2. 每个工作包的流程

每个工作包都按这个顺序走，不跳步：

1. **定设计。** 改动超过几处文案时，先把设计给 Lewis 看，得到同意再写代码。
2. **开分支。** 从集成分支 `release-1.0` 开，分支名用工作包编号，比如 `w2-progress-card`。
3. **先写测试。** 看着测试因为功能缺失而失败，排除拼写错误这类假失败。
4. **实现。** 只做这个工作包范围内的事，发现别的问题就记到第 8 节。
5. **自动检查。** `npm run typecheck`、`npx vitest run`、相关验收场景，中英文都跑。
6. **看截图。** 只有真正打开看过的图才算看过，没看的要写明。
7. **更新文档。** 更新 `CHANGELOG.md` 的 “Unreleased (1.0)”、`tools/README.md`，以及本文的状态。
8. **开 PR。** 描述里写清查过什么、没查到什么，由 Lewis 决定是否合并。

固定规则：

- git 身份是 `Ziming Dong <24kplo@gmail.com>`。提交信息用英文，提交、代码和文档都不留 AI 痕迹。
- 花钱、推标签、删除东西之前先问。
- 真实运行只用 `LAMPLIGHT_TEST_KEY`，每单上限 $0.40，跑之前先报预算。
- 验收默认用替身，不花钱，窗口留在屏幕外。
- 给 Lewis 的命令用 PowerShell，一行一条。

### W7 角色交互

**第一阶段（不用新美术）：**

**第二阶段（要新美术，见 D1）：**

- 手持道具：可以用分层合成，比如把杯子和书做成跟随手部的小精灵。

**完成标准：**

- 规则测试确认每种事件对应的动作都是真实动画。
- `rules/anim-fallback.yaml` 里的代替项减少，每条保留的都有理由。
- 小猫不再滑行。

**做法：** 两个阶段一起做完了，新美术都是自己画的，没有动 LimeZu 的素材。

- 写字是桌上一张纸和一支会动的笔，喝水和转杯子是手里的杯子，敲打是手里的锤子，都在 `app/renderer/game/props.ts`。走开时道具收掉。
- 小猫走路是 `scripts/art/characters.py` 画的四帧，向左走时翻转，到了又趴下。

- 没做：递东西时两人走到一起再交接。派活时对方常常在店的另一头，走过去会拖慢真实进度的表现。
