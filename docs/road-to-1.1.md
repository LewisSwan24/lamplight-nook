# 小灯屋 1.1 工作流

基线：`main` 的 `0015c3a`（2026-11-14）。文中的 `路径:行号` 都对应这个提交，代码改动后行号会漂移。

这份文档是 1.1 的唯一工作清单，展开的是 `docs/road-to-1.5.md` 第 3 节。下面的工作包全部完成，并且通过第 6 节的发布关卡，才发 1.1。

## 1. 目标

一个陌生人能从商店或官网装上小灯屋，用上几个月不出问题：

- **装得上：** 安装包有签名，商店里搜得到，Mac 上也能用。
- **跟得上：** 有新版本时小店自己知道，用户点一下就能更新，数据不丢。
- **算得清：** 花的钱和 Anthropic Console 对得上，每单用了多久、卡在哪里，本机都有记录。
- **用得深：** 能在自己已有的文件夹里干活，做好的东西能导出带走。
- **看不腻：** 第 20 单以后还有新东西，季节和节日都有变化。

## 2. 流程

照 `docs/road-to-1.0.md` 第 2 节，有两处不同：

1. 集成分支是 `release-1.1`，从 `main` 开。工作包分支从它开，名字用编号，比如 `a1-updates`。
2. CHANGELOG 写在 “Unreleased (1.1)” 下面。

### A4 本地使用统计

**现状：** 每单在 `memory.json` 里记了花费、结果和会话号（`app/shared/types.ts:345-359`），没记用时，失败只记 `failed`，不记原因。用时只写进日志（`app/main/index.ts:356`）。排队跑腿的次数只在渲染进程里数（`app/renderer/translator/translator.ts:83-136`），用完就丢。

**设计：**

- 每单多记几项：用时（秒）、几轮、每次失败的原因、每种帮手各接了几次活、跑腿排了几次队、等了多久。
- 只存在本机的 `memory.json` 里，不上传。导出诊断时默认不带。
- 笔记本加一页“小店账簿”：这个月接了几单、平均用时、花了多少、最常见的失败原因、跑腿排队的次数。
- “忘掉一切”时一起清掉，也能单独清。
- 1.1 以前的老作品没有这些数据，账簿里写明从哪天开始记。

**要说清楚的一点：** 数据只在本机，所以 Q-A3 能参考的只有 Lewis 自己的使用和测试录制，看不到别的用户。

**完成标准：** 新加的字段有单元测试。新场景 `stats` 跑三单，其中一单失败、一单有排队，账簿上的数字都对。旧数据打开不报错，`upgrade` 场景过。

### A7 模板改成一张表，加四种新模板

**现状：** 模板没有统一的登记处。加一种模板至少要改 `types.ts`、`commission.ts`、`panels.ts`、`growth.ts`、`ShopGrowth.ts`、一张贴图和两份语言文件，要选文件的还要改 `index.ts` 和 `guests.ts`。提示词在 `app/main/commission.ts:112-176` 的 `switch` 里。

**设计：**

- 每种模板一条记录，放在 `app/shared/templates.ts`：编号、表单字段、提示词、要不要选文件、主文件偏好、对应的成长物件和客人。语言文件里的文字照旧按编号查。
- 先把现有八种搬进去，行为一点不变：`templates` 场景和截图在搬之前和搬之后要一样。
- 再加四种。候选是简历、读书笔记、旅行攻略和小工具脚本，Q-A4 定。小工具脚本会让 Claude 写可以运行的代码，要和安全规则一起看。
- 每种新模板配一件成长物件，贴图用现有素材包拼。

**完成标准：** 加第五种以后的模板只改 `templates.ts`、语言文件和贴图。四种新模板各用替身跑通 `templates` 场景，各用真 Key 跑一单，截图和产物都看过。

### A6 在已有文件夹里干活

**现状：** 每单都按标题在工作目录下新开文件夹（`app/main/index.ts:419-420`）。开工前记下文件夹里原有的东西，叫 `preexisting`（`index.ts:424`）。改原有的文件算严重操作，要弹卡片问（`app/main/risk-classifier.ts:265-281`）。版本只存小店做出来的顶层文件，上限 50MB（`app/main/versions.ts`）。挪走的作品可以重新找回，太大的文件夹会被拒绝（`index.ts:463-466`）。

**设计：**

- 委托单上加一个选项：“在我已有的文件夹里改”，选一个文件夹。磁盘根目录、用户主目录、文档、桌面、下载这些太大的位置照旧拒绝，复用 `holdsTooMuch`。
- 开工前用户确认一次。之后改原有文件不再每次弹卡，但每个文件第一次被改之前，先把原样复制一份到版本库。删除和跑命令照旧要问。
- 撤回这一单：放回所有改过的文件，删掉这一单新做出来的文件，用户别的文件不动。
- 版本库为这种作品单独算上限。超过上限就不让开工，并说明原因，不能做到一半才发现没法撤回。
- 结果卡写清这一单改了哪些原有文件、新做了哪些。

**完成标准：** 新场景 `inplace` 覆盖三件事。改两个原有文件再撤回，内容逐字节还原；太大的文件夹被拒；超过上限时开工前就拦下。用真 Key 在一个小网站文件夹里跑一单改动，再撤回一次。

### A8 作品导出

**现状：** `app/main/zip.ts:6` 能打压缩包，只用在导出诊断（`index.ts:193-216`）。作品能打开文件或文件夹，没有导出，也没有转 PDF。

**设计：**

- 作品架每件作品加“带走”：打成压缩包，存到用户选的位置。
- 主文件是网页的，可以另存成 PDF，用隐藏窗口的 `printToPDF`。
- A6 那种在已有文件夹里改的作品，只打包这一单碰过的文件。
- 不经过任何服务器，“分享”就是生成文件，交给用户自己发。

**完成标准：** 新场景 `export` 导出压缩包和 PDF，解开后的文件和原作品一样，PDF 页数和文字对得上。中英文都过。

### A1 自动更新和签名

**现状：** 没有任何更新代码（`package.json` 里没有 `electron-updater`）。打包只出 NSIS 安装包，没有签名配置（`package.json:64-75`），`release.yml` 也没有签名步骤。Electron 是 38，electron-builder 是 26。

**设计：**

- 用 `electron-updater` 从 GitHub Releases 检查新版本。`release.yml` 多上传 `latest.yml` 和差分文件。
- 打开时查一次，之后每六小时查一次。有新版本，邮差送来一封信，写着版本号和更新内容。
- 用户点“更新”才下载。下载好以后，等这一单做完、用户关掉小店时再装，绝不在委托做到一半时重启。
- 更新前备份数据文件夹，沿用 `migrate.ts` 现有的备份做法。
- 商店版不检查更新，交给商店。
- 签名看 Q-A1。没签名也能自动更新，只是首次安装时 SmartScreen 照旧会拦。

**完成标准：** 验收里用一个本地更新源，从 1.1.0 升到 1.1.1：送信、下载、关店时安装、数据都在。委托进行中不会被打断。真机上从 GitHub 实测一次，放到 A12。

### A2 微软商店上架

**现状：** `scripts/msix.mjs` 自己拼 MSIX，身份信息从环境变量读，不给就用测试身份（`scripts/msix.mjs:22`、`:304-307`）。1.0 时 Windows 拒绝安装没签名的包，报 `0x80073D2B`（README:83-85）。商店版只给安装 Claude Code 的步骤，不替用户运行安装程序（`app/main/index.ts:160-164`、`:244`）。数据都在 `userData` 下面，MSIX 会把它放进包自己的私有目录，代码里没有处理这种情况。

**设计：**

- 用自签名证书给测试包签名，在本机装上。证书要装进系统的受信任列表，这一步由 Lewis 自己操作，我写好步骤。
- 查清两件事：商店版的数据实际写在哪里；从安装包版换到商店版时，旧的作品和账本能不能读到。读不到就加一次“搬家”：商店版第一次打开时发现旧数据，问用户要不要搬过来。
- 在 Partner Center 用 Lewis 的账号保留名字，拿到正式身份信息，填进 `release.yml` 的变量。
- 提交审核，按审核意见改到通过。

**完成标准：** 测试包在真机装上、打开、跑一单替身委托。从安装包版换到商店版，作品和账本都在。商店审核通过，或者把被拒的原因记下来。

### A3 真机账目和遗留验证

**现状：** 1.0 发布关卡里还有几项没做。花费没和 Console 对过，预算卡的“接着做”和“看看已经做好的”没真点过。声音、讲述人和缩放没有逐项记录。每周的真实回归在跑，但仓库里没有 `LAMPLIGHT_TEST_KEY`，日志写着 `HAS_KEY: false`，只跑了替身那一半。

**设计：**

- 我把账本里每个会话的花费列成一张表，Lewis 在 Console 里对同一时段，差多少记下来。
- 预算卡的两个按钮用真 Key 各点一次，预算约 $3。
- 声音、讲述人、125% 和 150% 缩放，按清单逐项过，每项写“过”或“不过，现象是什么”。
- 每周回归的测试 Key 放哪里由 Q-A7 定。Key 由 Lewis 自己填，我不碰。

**完成标准：** 对账表写进本文第 7 节，差额有解释。清单每项都有结果。每周回归连续两周真跑了真实那一半。

### A9 第 20 单以后的成长

**现状：** 成长物件按完成数解锁，最后一件是第 50 单的星星（`app/shared/growth.ts:10-28`）。菜园 8 块地，第 25 单全部熟透（`growth.ts:63-83`）。客人 5 位（`app/renderer/game/guests.ts:14-25`）。已有季节和天气，节日只有万圣节、圣诞和春节（`app/renderer/game/weather.ts:60-71`）。

**设计：**

- 成长线延长到第 100 单：在 60、75、100 单各加一件大物件，在中间补几件小的。
- 菜园全熟以后不再静止：按季节换种，秋天收获，冬天休耕。
- 每个季节有自己的店内摆设，节日加中秋、端午和元宵，名单由 Q-A5 定。英文用户看到的节日要不要不同，也在 Q-A5 定。
- 街坊在第 20 单以后有新话题，按季节和节日轮换。

**完成标准：** `beds` 和 `days` 场景扩展到 100 单，每个新物件都出现过。每个季节和每个节日都有截图，中英文都看过。

### A5 学徒

**现状：** 主代理驱动阿灯。三个子代理 researcher、designer、reviewer 分别对应小橘、青黛、老石，不认识的子代理都交给小橘（`app/renderer/translator/translator.ts:34`）。小橘和老石一次只接一件活，多的排队（`translator.ts:83-136`）。三个子代理都没指定模型（`app/main/agent-runner.ts:25-41`）。加一个角色要改十几个文件，还有 `rules/` 和 `lines/` 下的台词。

**两种做法，Q-A3 定：**

- **表演角色：** 学徒只接排队的活。小橘忙的时候，第二件查资料的活交给学徒，不再干等。不多花钱。
- **真帮手：** 加一个检查员子代理，专门跑检查和测试，学徒就是它。每单会多花钱，先用真 Key 量过多花多少，预算约 $4。

**两种都要做的：** 学徒的贴图和走路，台词，进出店的路线，成长和街坊对学徒的反应。

**完成标准：** 有排队的场景里学徒接活，截图看过。选真帮手的话，用真 Key 跑三单，记下每单多花的钱。

### A10 macOS 版

**现状：** 打包配置只有 Windows（`package.json:64-75`），没有 `.icns` 图标。找 Claude Code 和安装命令已经分了平台（`app/main/claude-locator.ts:22-63`）。Key 用 `safeStorage` 加密，Mac 上走钥匙串。字体先写微软雅黑后写苹方（`app/renderer/style.css:1`），小窗口的样式里没有苹方（`app/renderer/mini.css:4`）。

**设计：**

- 加 Mac 的打包目标，签名和公证。需要 Apple 开发者账号，要花钱，Q-A2 一起定。
- 托盘在 Mac 上变成菜单栏图标，用模板图。关掉窗口的行为照 Mac 的习惯。
- 字体顺序按平台调整。
- `release.yml` 加一个 macOS 的任务，构建可以在 GitHub 的 Mac 机器上做，真机测试要一台真的 Mac。

**完成标准：** 在真 Mac 上装上、引导安装 Claude Code、用真 Key 跑一单，约 $1。关键场景在 Mac 上用替身跑过。
