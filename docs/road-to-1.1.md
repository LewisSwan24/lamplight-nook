# 小灯屋 1.1 工作流

基线：`main` 的 `0015c3a`（2026-11-14）。文中的 `路径:行号` 都对应这个提交，代码改动后行号会漂移。

这份文档是 1.1 的唯一工作清单，展开的是 `docs/road-to-1.5.md` 第 3 节。下面的工作包全部完成，并且通过第 6 节的发布关卡，才发 1.1。

## 1. 目标

一个陌生人能从商店或官网装上小灯屋，用上几个月不出问题：

- **装得上：** 安装包有签名，商店里搜得到，Mac 上也能用。
- **跟得上：** 有新版本时小店自己知道，用户点一下就能更新，数据不丢。
- **算得清：** 花的钱和 Anthropic Console 对得上，每单用了多久、卡在哪里，本机都有记录。
- **用得深：** 能在自己已有的文件夹里干活，做好的东西能导出带走。
- **看不腻：** 第 20 单以后还有新东西，季节和节日都有变化。

## 2. 流程

照 `docs/road-to-1.0.md` 第 2 节，有两处不同：

1. 集成分支是 `release-1.1`，从 `main` 开。工作包分支从它开，名字用编号，比如 `a1-updates`。
2. CHANGELOG 写在 “Unreleased (1.1)” 下面。

### A7 模板改成一张表，加四种新模板

**现状：** 模板没有统一的登记处。加一种模板至少要改 `types.ts`、`commission.ts`、`panels.ts`、`growth.ts`、`ShopGrowth.ts`、一张贴图和两份语言文件，要选文件的还要改 `index.ts` 和 `guests.ts`。提示词在 `app/main/commission.ts:112-176` 的 `switch` 里。

**设计：**

- 每种模板一条记录，放在 `app/shared/templates.ts`：编号、表单字段、提示词、要不要选文件、主文件偏好、对应的成长物件和客人。语言文件里的文字照旧按编号查。
- 先把现有八种搬进去，行为一点不变：`templates` 场景和截图在搬之前和搬之后要一样。
- 再加四种，Lewis 2026-11-14 定的：简历、读书笔记、旅行攻略和小工具脚本。设计见下面的表，他说“按这个设计做”。
- 每种新模板配一件成长物件，贴图用现有素材包拼。

| 模板 | 交出 | 能递的材料 | 规则 | 成长物件 |
|---|---|---|---|---|
| 简历 | `resume.html`，一页 A4，浏览器打印成 PDF | 旧简历或经历清单 | 经历、学历、日期和数字一律不编，缺的留方括号；最后说明按什么岗位侧重 | 公文包 |
| 读书笔记 | `读书笔记.md`，英文版叫 `reading-notes.md`：总结、要点、摘录、留给自己的问题 | 摘抄和随手记 | 摘录只从递来的材料里摘；作者、年份可以让小橘查，查不到写明 | 读书灯 |
| 旅行攻略 | `index.html`：按天的行程、预算表、要带的东西、地图链接 | 无 | 开放时间和票价由小橘上网查，注明出处和日期，提醒出发前核对 | 明信片 |
| 小工具脚本 | 优先做网页工具 `tool.html`；要改文件时才写 PowerShell 脚本，配双击启动的文件 | 样例文件 | 脚本默认只演练，加确认参数才动手；试运行只用委托文件夹里的样例，不碰真实文件 | 工具箱 |

小工具脚本的 PowerShell 一支只做 Windows，Mac 版要换成 shell 脚本。

小工具的规矩（先演练、加 `-Apply` 才动手、不删除）原本只写在提示词里。2026-11-15 按 Lewis 说的“加扫描检查，结果卡上提醒”补了一道。每轮做完，应用把文件夹里所有的 `.ps1`、`.cmd` 和 `.bat` 都读一遍。旧的也读，因为后一轮可能改过。读的时候认 UTF-16，去掉注释后找删除命令。PowerShell 脚本没有 `-Apply` 开关，或者启动文件直接带上 `-Apply`（含 `-Ap` 这类缩写），都算不先演练。有问题的脚本，结果卡上用红字点名。应用本来就不会替用户打开脚本，只在文件夹里选中。

这道检查用正则，挡的是店员写错，挡不住存心绕开的写法：`Invoke-Expression`、拆开的命令名、调用外部程序删除，都认不出来。子文件夹里的脚本也不看。

旅行攻略真跑一轮花了 $1.05。每轮上限设成 $1 的人第一轮就会被停下，要不要在选这种模板时提醒一句，合并前和 Lewis 定。

**完成标准：** 加第五种以后的模板只改 `templates.ts`、语言文件和贴图。四种新模板各用替身跑通 `templates` 场景，各用真 Key 跑一单，截图和产物都看过。

### A6 在已有文件夹里干活

**现状：** 每单都按标题在工作目录下新开文件夹（`app/main/index.ts:419-420`）。开工前记下文件夹里原有的东西，叫 `preexisting`（`index.ts:424`）。改原有的文件算严重操作，要弹卡片问（`app/main/risk-classifier.ts:265-281`）。版本只存小店做出来的顶层文件，上限 50MB（`app/main/versions.ts`）。挪走的作品可以重新找回，太大的文件夹会被拒绝（`index.ts:463-466`）。

**设计：**

- 委托单上加一个选项：“在我已有的文件夹里改”，选一个文件夹。磁盘根目录、用户主目录、文档、桌面、下载这些太大的位置照旧拒绝，复用 `holdsTooMuch`。
- 开工前用户确认一次。之后改原有文件不再每次弹卡，但每个文件第一次被改之前，先把原样复制一份到版本库。删除和跑命令照旧要问。
- 撤回这一单：放回所有改过的文件，删掉这一单新做出来的文件，用户别的文件不动。
- 版本库为这种作品单独算上限。超过上限就不让开工，并说明原因，不能做到一半才发现没法撤回。
- 结果卡写清这一单改了哪些原有文件、新做了哪些。

**完成标准：** 新场景 `inplace` 覆盖三件事。改两个原有文件再撤回，内容逐字节还原；太大的文件夹被拒；超过上限时开工前就拦下。用真 Key 在一个小网站文件夹里跑一单改动，再撤回一次。

**做法（2026-11-15）：**

- 委托单上多了一行链接“在我已有的文件夹里改…”，选文件夹走主进程的对话框。太大的位置照旧由 `holdsTooMuch` 拒绝。用户的文件合计超过 100MB（`MAX_LENT_BYTES`）也不收，在单子上就说明原因。示范、改文档、整理文件夹和相册要用小店自己的文件夹，所以不显示这一行。
- 交单时，单子换成一个问题：就在这个文件夹里改吗？说清原有文件会被直接改，以及怎么撤回。默认停在“回去再看看”上，按回车不会开工。
- 原有文件用 Write 或 Edit 改时不弹卡。放行之前，先把原样复制到版本库的 `lent/<文件夹的哈希>/` 下，每个文件只在第一次改之前存一回。用命令写同一个文件、删除和跑命令，照旧弹卡。
- 撤回就是结果卡上的“撤回这一单”，点两下才生效。改过的文件逐字节放回，这一单新建的文件和空文件夹拿走。用户后来放进新文件夹里的东西不动。
- 结果卡分两行写清改了哪些原有文件、新做了哪些。主文件优先找新做的，没有就从改过的里找。
- 开工和再改一轮之前，都会重新量一次文件夹。超过上限就弹“这个文件夹变大了”，什么都不改。
- 后台安全审查指出三处，都先补测试再修。第一处：点号开头的文件夹或文件（`.git`、`.github`、`.vscode` 等）、能运行的文件（`.ps1`、`.cmd`、`.bat`、`.exe`、`.com`、`.msi`、`.vbs`、`.sh` 等）和 `package.json`，改之前照旧弹卡。普通的 html、css、js、md、数据和图片不弹。第二处：用户文件夹里的链接或目录联接可能把写入引到外面，现在按真实路径判断，落在外面就弹卡。第三处：撤回时写回和删除都不跟着链接走。落到文件夹外面的那几个跳过，结果卡点名说没放回。
- 修这三处时又发现一个漏洞，也先写了测试。路径写成 `C:/x/a.html`，或者在 Windows 上大小写不同，原来认不出是用户的文件，会不存原样就直接改。现在先把路径规整好再比，Windows 上不分大小写。审查又指出，区分大小写的文件夹里可能有两个只差大小写的文件。现在先找写法完全一样的那个；找不到时，只差大小写的恰好一个才算数，有好几个就照旧弹卡。

**暂定：**

- 选了自己的文件夹，就不能再递材料。材料要复制进用户的文件夹，可能和用户的文件重名。
- 撤回只在结果卡上，关掉卡片就找不到了，作品架上没有入口。原样一直留在版本库里，以后补个入口就行。
- 撤回后作品照旧留在作品架上。
- 同一个文件夹里又开了新的一单，上一单就不能再撤回了。不然撤回旧的，会把新一单的改动一起抹掉。
- 店员经用户同意删掉的原有文件，撤回时放不回来，因为改之前没存。

### A8 作品导出

**现状：** `app/main/zip.ts:6` 能打压缩包，只用在导出诊断（`index.ts:193-216`）。作品能打开文件或文件夹，没有导出，也没有转 PDF。

**设计：**

- 作品架每件作品加“带走”：打成压缩包，存到用户选的位置。
- 主文件是网页的，可以另存成 PDF，用隐藏窗口的 `printToPDF`。
- A6 那种在已有文件夹里改的作品，只打包这一单碰过的文件。
- 不经过任何服务器，“分享”就是生成文件，交给用户自己发。

**完成标准：** 新场景 `export` 导出压缩包和 PDF，解开后的文件和原作品一样，PDF 页数和文字对得上。中英文都过。

**做法（2026-11-15）：**

- 作品架每一行多了“带走”。主文件是网页的，点了先在这一行问要压缩包还是 PDF；别的作品直接存压缩包。存的位置由主进程的对话框选，默认在桌面，文件名取作品名，去掉 Windows 不收的字符。存好后在文件夹里选中它。取消就什么都不写。
- 小店自己文件夹里的作品，压缩包里是文件夹里的全部文件，子文件夹照旧。链接和目录联接不打进去，免得把文件夹外面的东西带出去。
- 在用户自己文件夹里改的作品，只打包这一单改过和新做的文件。这份清单记在笔记本里，叫 `touched`，每轮改动都往里加。版本库那份记录在撤回、挪走或同一文件夹开新单时就删掉了，笔记本这份还在。撤回以后只剩没放回的那几个，全放回了就是空的，作品架会说没有东西可带走。
- PDF 用一个隐藏窗口打开主文件，再调 `printToPDF`，纸张 A4，带背景色。窗口没有预加载脚本，不开 Node，开着隔离和沙箱，用一个不落盘的单独会话，权限请求一律拒绝。全局规则照旧挡住跳转和新窗口。页面里的脚本照常运行，有的页面靠它画内容。做完就关掉窗口。
- 安全审查指出，隐藏窗口原来什么都能读。页面可以引用电脑上别的文件或网上的东西，印进用户要发出去的 PDF。现在先补了测试再修。页面只能读作品文件夹里的文件，按链接跟到底的真实路径算。别的文件地址、网络地址和别的电脑上的共享文件一律拦下。共享文件在碰磁盘之前就拦，不然会去连那台电脑。写在页面里的 `data:` 数据照常放行。后续审查又加了两层。每次打 PDF 都用一个新的临时会话，两份同时打也不会共用规则。会话还配了一个哪儿也连不上的代理，代理之外的 WebRTC 也关掉了。
- 场景 `export` 用系统自带的 `tar` 解开压缩包，不用小店自己的代码。PDF 的文字靠 `tools/sim/pdftext.mjs` 读，它解压内容流，再按字体的 ToUnicode 表把字形号换回文字，没有加依赖。字体有时把“页”映射成长得像的部首，所以比对时部首可以顶替任何汉字。

**暂定：**

- 压缩包和 PDF 都整个放在内存里再写盘，也不支持 zip64。超过 4GB 的作品打出来会坏。小店文件夹里的作品一般远小于这个，借来的文件夹本身限 100MB，所以先不处理。
- PDF 只打主文件那一页。靠滚动才显示、或者带进场动画的内容，印出来可能是空的。
- 页面引用网上的字体和图片，在 PDF 里会缺。这是有意的，代价是有些页面印出来和在浏览器里看到的不一样。

### A1 自动更新和签名

**现状：** 没有任何更新代码（`package.json` 里没有 `electron-updater`）。打包只出 NSIS 安装包，没有签名配置（`package.json:64-75`），`release.yml` 也没有签名步骤。Electron 是 38，electron-builder 是 26。

**设计：**

- 用 `electron-updater` 从 GitHub Releases 检查新版本。`release.yml` 多上传 `latest.yml` 和差分文件。
- 打开时查一次，之后每六小时查一次。有新版本，邮差送来一封信，写着版本号和更新内容。
- 用户点“更新”才下载。下载好以后，等这一单做完、用户关掉小店时再装，绝不在委托做到一半时重启。
- 更新前备份数据文件夹，沿用 `migrate.ts` 现有的备份做法。
- 商店版不检查更新，交给商店。
- 签名看 Q-A1。没签名也能自动更新，只是首次安装时 SmartScreen 照旧会拦。

**完成标准：** 验收里用一个本地更新源，从 1.1.0 升到 1.1.1：送信、下载、关店时安装、数据都在。委托进行中不会被打断。真机上从 GitHub 实测一次，放到 A12。

**做法（2026-11-15）：**

- 用 `electron-updater` 查 GitHub Releases。`package.json` 写明发布到 GitHub，打包时就会把 `app-update.yml` 放进应用，旁边生成 `latest.yml` 和安装包的 blockmap，用不着真的发布。`release.yml` 把这两个文件和安装包一起传上去。本机打过一次安装包，三个文件都生成了。
- 逻辑都在 `app/main/updates.ts`，不碰 Electron，单元测试直接测。窗口第一次载入完查一次，之后每六小时查一次，商店版一次都不查。设置的“关于”页有个开关，默认开着。关了就不查，重新打开时马上查一次。商店版不显示这个开关。
- 查到新版本只记下来，不下载。店里闲着、桌上没有卡片的时候，阿信从前门进来，在柜台递上信。信上有版本号和更新内容。GitHub 给的更新内容是网页，中英两段都在里面，信里只留店里用的语言。同一个版本每次开店只送一次。阿信还没递信就被委托叫走的话，下回再送。
- 点“更新”才下载，下载好了阿灯说一声。真正关店时才装，关到托盘不算。装之前照 `migrate.ts` 的做法，把四个数据文件复制到 `backup/<日期>-before-<版本>/`，复制失败就不装。安装包静默运行，装完不会自己打开小灯屋。
- 委托做到一半时关店，照旧先问“继续做”还是“停下并关闭”。选停下的话，委托照旧停下，下次开店还能接着做，安装包随后运行。
- 查不到新版本（没联网、GitHub 连不上）只在日志里记一行，用户什么都看不到。下载失败时阿灯说一声没取到，下回查到再送信。
- 场景 `update` 自己起一个本地 HTTP 更新源，通过 `LAMPLIGHT_UPDATE_CONFIG` 指给应用。这个变量只在没打包时生效。模拟时不运行安装包，日志里记一行代替。开发版的版本号取 `package.json` 里的 1.0.0，所以更新源给的是 1.1.1。
- 模拟运行给 Electron 装了一层替身，`electron-updater` 是 CommonJS，经由 `import` 载入时找不到它，应用一开就报错。`tools/sim/isolate.cjs` 补了一个 CommonJS 版的替身。
- `electron-updater` 带进来的 `argparse` 用 Python 软件基金会许可证，`lazy-val` 没附许可证全文。前者加进人工审过的名单，后者按 MIT 补上全文。

**暂定：**

- Q-A1 不签名。首次安装时 SmartScreen 照旧会拦，自动更新不受影响。`electron-updater` 只在 `app-update.yml` 写了发布者时才核对签名，现在没写。以后签了名，要把发布者写进打包设置。
- Q-A8 默认开，只查不下载。
- 点了“先不了”，这次开店不再送同一个版本的信，下次开店再送。这个选择没有存下来。
- 换场景会重新载入页面，没递出去的信这次就丢了，下次开店再送。
- 下载到一半关店，什么都不装，下次开店重新查。
- 选“停下并关闭”以后，安装包不等委托收尾。Claude Code 靠停止信号结束，和今天关店一样。
- 新美术一张没加，阿信用的是现有的邮差贴图。
- 仓库现在是私有的。装好的应用不带令牌去问 GitHub，拿到的是 404，所以发 1.1 之前什么新版本都看不到，只在日志里记一行。要么把仓库公开，要么把安装包发到一个公开的仓库或网站上，再改 `package.json` 的发布设置。这件事等 Lewis 定，A12 之前要定下来。
- `npm run packaged` 只打文件夹，不打安装包，electron-builder 这时不写 `app-update.yml`，所以那次检查里应用找不到更新源。`app-update.yml` 的内容在 `npm run dist` 解开的应用上查过。

### A5 学徒

**现状：** 主代理驱动阿灯。三个子代理 researcher、designer、reviewer 分别对应小橘、青黛、老石，不认识的子代理都交给小橘（`app/renderer/translator/translator.ts:34`）。小橘和老石一次只接一件活，多的排队（`translator.ts:83-136`）。三个子代理都没指定模型（`app/main/agent-runner.ts:25-41`）。加一个角色要改十几个文件，还有 `rules/` 和 `lines/` 下的台词。

**两种做法，Q-A3 定：**

- **表演角色：** 学徒只接排队的活。小橘忙的时候，第二件查资料的活交给学徒，不再干等。不多花钱。
- **真帮手：** 加一个检查员子代理，专门跑检查和测试，学徒就是它。每单会多花钱，先用真 Key 量过多花多少，预算约 $4。

**两种都要做的：** 学徒的贴图和走路，台词，进出店的路线，成长和街坊对学徒的反应。

**完成标准：** 有排队的场景里学徒接活，截图看过。选真帮手的话，用真 Key 跑三单，记下每单多花的钱。

**做法（2026-11-15）：**

- 学徒叫小豆，英文叫 Bean，代号 `xiaodou`。贴图在 `scripts/art/characters.py` 里用同一套人物素材拼，红豆色的头发，头顶翘一撮，穿绿衬衫。走路、站立和递东西的帧跟另外四人一样，头像也加了一行。
- 小豆第 10 单以后来店里，门槛写在 `app/shared/staff.ts`。做完第 10 单那天，小豆从街上经过窗外，推开前门走到柜台前，阿灯介绍一句，小豆接一句。以后开店小豆就在柜台前站着。笔记本里店里的日子多了一行“小豆来店里当学徒”。把记忆全忘掉，小豆也跟着走。
- 只接小橘的活。小橘出门跑腿时又来一件查资料的活，就交给小豆，小豆也从前门出去。小豆也出去了，第三件照旧排队，谁先回来谁接。没认出来的子代理本来归小橘，也一样。老石的检查不归学徒，第二件照旧等老石。
- 规则文件里多了 `when.by`。两条学徒的规则写在小橘那几条前面，出门和回来都有自己的台词。开店、做完和取消时，小豆跟别人一样回到自己的位置。来店之前，翻译器不给小豆发任何指令。
- 回柜台交东西的是谁，包裹上就写谁的名字。街上的小窗只画先出门的那个，后出门的在窗外走过就不见了。
- 中英文台词各加了出门四句、回来四句、来店那天一句，后院喂鸡和菜地各两句。闲聊四段，里面有一段只讲一次的小豆头一天来。桂姨和阿信各有一段说到小豆。台词检查照旧都过，手写字体不缺字。
- 小豆在每个地方都有自己的站位。窗边的位置起先和留声机打架，`routes` 测试报了七条走法，挪到了黑板下面。
- 新场景 `apprentice` 分两段。第一段从 9 单开店，小豆不在；做完第 10 单，小豆走进来，介绍的话说完了。第二段让替身同时派出三个查资料的子代理。场景查小橘和小豆同时在外面，第三件排了队，小豆回到柜台说了话。

**暂定：**

- Q-A3 暂定为表演角色，不加子代理，不换模型，不多花钱。
- 名字定为小豆和 Bean，跟阿灯、小橘、老石、青黛一样取个常见的东西。
- 第 10 单来店。第 8 单的吉他和第 12 单的盆景中间正好空着。
- 只帮小橘跑腿，不帮老石检查。学徒还在学，检查要看手艺。
- 回来的顺序按出门的先后算。事件里分不出是哪个子代理先做完，包裹里的内容不会错，署名的人可能对不上。
- 小豆走得比小橘慢一点，比别人快。站的地方是柜台前面客人那一侧，跟阿灯隔着柜台。
