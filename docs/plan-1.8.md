2026-11-25 写，照 `docs/road-to-2.0.md` 第 6 节细化。1.6 和 1.7 加起来新增约一万一千五百行，离 Lewis 要的两万行还差八千五百行左右。照 1.7 计划第 2 节的约定，接着写 1.8 的计划。

1. **分支。** `release-1.8` 从 `release-1.7` 开，每个包一条分支，PR 合进 `release-1.8`。1.7 还没发布，版本号、标签和合进 `main` 都等 Lewis 说。

3. **新委托的规矩照 1.1。** 一位常来的客人，一件长出来的东西，提示词的快照测试，一个用替身 Claude 的场景，中英文都有。

## 4. 工作包

### H0 Word 文档的复核和样式

**现状：**

- 老石是复核的子代理，只有 `Read`、`Glob`、`Grep` 三样工具（`app/main/agent-runner.ts:44-45`）。`Read` 读不了 .docx，店里的 `office` 工具有 `read_document`（`app/main/office/tools.ts:186`），老石用不到。
- 1.7 的两单真委托（G5、G6）都出了 Word 文档，老石都回“打不开”，店里只好自己读一遍。中文那单还说设计方案里的配色和字号做不出来，文档用的是默认样式。

**设计：**

- 老石的工具里加上 `read_document`，只读，不能改文件。提示词里说清楚：Office 文件用它读。
- 查清楚配色和字号为什么做不出来：是 `make_document` 不收这些参数，还是提示词没让它传。能补的补上，补不了的在提示词里别再让设计师定。

**完成标准：** 单元测试：老石的工具里有 `read_document`，没有写文件的工具。真 Key 约 $1：递一单出 Word 的委托，老石的复核里说得出文档里的内容，文档用上了设计的颜色。

**做法：**

- 老石和青黛的工具里都加上了 `read_document`，提示词里说清楚 Office 文件要用它读。两人还是不能写文件。
- 配色做不出来，是因为 `make_docx` 本来就只收标题、段落、列表、表格和图，没有颜色和字号。现在加了两个可选的参数：`accent` 是标题、各级小标题和表头的颜色，`size` 是正文字号，9 到 16 磅。不给就是原来的样子。
- 青黛的提示词里加了一句：给 Word 文档出方案，只出一个主色和正文字号，别的做不出来。
- 真 Key 跑了一单（中文，“写份 Word 文档”，圣诞晚餐菜单），1 分钟、$0.17。录像里老石调了 `read_document`，权限放行，没有被拒；他的复核挑出了火鸡份量对不上，说明真读到了内容。文档的标题和小标题是酒红色 `8B1E2D`。

### H7 作品架按店筛

**现状：** 作品架已经能搜字、按种类筛，作品多了按月份分组（`app/renderer/ui/shelf.ts:81-113`，`app/shared/shelf.ts`）。不能按店筛。二十种委托分在主店、印刷铺、画室、工坊、面包房、邮局六处（`app/shared/templates.ts`）。

**设计：** 筛选那一行加一排店名，点一间只看那间店做的。跟种类、搜字可以叠着用。店名用街上的招牌字。

**完成标准：** 单元测试：按店筛、跟种类叠着筛都对。1.1 的场景 `days` 放了一百件作品，在那里加一步：按印刷铺筛，数对得上。中英文截图看过。

**做法：**

- 作品架上的每件作品多了一个 `shop`，在 `app/main/memory.ts` 里用模板的店算出来。随手写的委托没有模板，图标虽然是网页，店还是算主店，不算工坊。示范那单也算主店。
- `ShelfFilter` 多了 `shop`，跟种类、搜字三样一起筛。`shopsOf` 按街上的顺序列出做过东西的店，主店在前，一件没做的店不出现。
- 种类那排下面加了一排店名，前面也有“全部”。点一排不动另一排。店名是街上的叫法：小灯屋、印刷铺、画室、工坊、面包房、邮局。
- 场景 `days` 的一百件里，每五件有一件改成 Word 文档（印刷铺），一件改成随手写的（主店）。这两种都不长新摆设，原来的检查照旧。新加的一步：按印刷铺筛出 20 件，再点“网页”就一件不剩，换成小灯屋又是 20 件。

### H1 复习卡片

**现状：** 没有。最近的是读书笔记（`notes`），出的是一篇笔记，不是卡片。

**设计：** 递一份材料（讲义、笔记、一章书），出两样东西：一套问答卡，做成能打印裁开的 PDF；一页小测，十道题，答案在背面。客人是一位要考试的学生。长出来的东西是主店书架上的一叠卡片。

**完成标准：** 快照测试锁住提示词。场景 `flashcards` 用替身 Claude 跑一单，中英文。真 Key 约 $3：拿一份真讲义跑一单，卡片的问答要出自材料。

**做法：**

- 新加一种委托 `flashcards`，在主店做。提示词要两样东西，都先排成 A4 的网页，再用 `make_pdf` 存成 PDF：
  - 问答卡：一页八张，两列四行，虚线好裁，角上标号。每页问题后面跟一页答案，左右两列对调，双面打印沿长边翻，答案正好在问题背面。
  - 小测：十道题，几种题型掺着出。第一页是题，第二页是答案，每个答案注明出自材料哪里。
- 提示词说死了：问题和答案都只从递过来的材料里出，不从记忆里补，也不替材料改错。材料看着有错，照原样留着，在回复里说。没有材料就请用户给，不凭空出卡片。卡片用材料的语言写。
- 成品卡上打开的是问答卡的 PDF。为此在 `MAIN_FILES` 里加了 `cards`，排在网页前面，不然打开的会是排版用的网页。
- 客人是乐乐，高三，书包里一半卷子一半卡片。中英文各九段话：平时四段，下雨一段，四季各一段。行走图用人物生成器拼，外套染成藏青。
- 长出来的东西是主店书架顶上一叠用皮筋扎着的卡片，摆在那摞书前面。书房的书架高一点，两个房间都摆得住，有没有那摞书都不挡。小橘看见了会说一句。
- 作品架上多了一个图标：一张白卡片压在一张米色卡片前面。
- 替身 Claude 的这一出，把材料里每一行“词：解释”做成一张卡，正面是“……是什么？”，背面是解释。
- 场景 `flashcards` 递一份九行的生物讲义，查这几样：
  - 两个 PDF 都在。
  - 卡片正好九张，每张都出自讲义。背面的号是 2、1、4、3，左右对调。
  - 小测十道题，十个答案。
  - 成品卡有缩略图，打开的是问答卡。
  - 书架上有那叠卡片，点一下阿灯会说来历。乐乐进门说话。
- 中英文都过，截图看过。
- 顺手改了一处旧账：F2 把简报那一摞挪到了窗台上，`pieces.json` 记的还是大桌上的旧位置，点不着。这次重做 `pieces.json`，一起改对了。

### H5 家庭账本

**现状：** 有“做个表格”（`sheet`），出的是一张普通的表。

**设计：** 印刷铺出一个 Excel 账本：每月一页，收入支出的分类可以改，月底自动出小结和一张饼图。不填数字也能用，空表本身就是成品。客人是社区里管家里账的阿姨。长出来的东西是印刷铺柜台上一本账簿。

**完成标准：** 快照测试；表里的公式用 `app/main/office/formula.ts` 查一遍算得对。场景 `ledgerbook`，中英文。真 Key 约 $3。

**做法：**

- 新加一种委托 `ledgerbook`，在印刷铺做，出一个 Excel 账本。提示词要这几样：
  - 每月一页，共十二个月，从要求里说的月份开始，没说就从一月开始。后面一页全年，最后一页分类。
  - 分类页一行一个分类，注明收入还是支出，下面留几行空的。改分类只在这一页改。
  - 每月那页记日期、摘要、分类、收入、支出、备注。分类那一栏是下拉单，选的是分类页上的名字。
  - 旁边是本月小结：收入、支出、结余，再按分类列出支出。分类名用公式从分类页取，金额用 SUMIF 算，改了名、加了分类都跟着变。
  - 每月一张支出饼图。全年那页用公式取每月的数，配一张每月支出的柱状图。
  - 一行记录也不填，空账本就是成品。要求里给了真数才填进去。
- `make_xlsx` 原来画不了图，这次补了三样：
  - 图表：饼图和柱状图，从本工作簿的一列或一行取数。
  - 下拉单：一栏的格子可以从一个区域或几个词里选。
  - 空格：单元格写 null 就留空，小结可以放在空着的几栏右边。
- 图表和下拉单里的区域照样过 `formulaProblem`，指到别的文件或网上的不收。做出来的账本照样过 `officeSafe`，点一下就能打开。
- `formula.ts` 原来只查公式安不安全，不会算。这次加了一个小算器 `computeBook`，照 Excel 的规矩算加减乘除、比较、跨页引用，还有 SUM、SUMIF、SUMIFS、COUNTIF、IF、IFERROR、ROUND 这些。认不得的函数给 `#NAME?`，不瞎猜。这个小算器有两个用处：
  - 成品卡的缩略图里，公式那一格显示算出来的数，不再显示公式本身。
  - 测试把替身做的账本读回来，填几笔账再算一遍。每月的收入、支出、结余，按分类的支出，全年合计，都对得上。改一个分类名、加一个分类，小结也跟着对。
- 长出来的东西摆在印刷铺的柜台上，照计划办。以前一种委托带来的东西只能摆在主店，街上的铺子只按单数长。这次模板上加了 `roomGrowth`：哪种委托做够几单，就在做它的那间铺子里长一件。`towngrow.ts` 的 `ROOM_WORK` 从模板里收这些东西，铺子自己的四件照旧按单数长。选这个办法有两个原因：
  - 账本是印刷铺做的，摆在印刷铺的柜台上才对得上。
  - 后面的小游戏、四格漫画、绘本也在街上的铺子做，都能用这一套。
- 柜台上是一本摊开的账簿：两页带格子的纸，一道红线，底下露出红布封面。做过一本账本就有，不管印刷铺做了几单。回到主店，阿灯会说印刷铺柜台上多了本账簿。
- 客人是秦阿姨，社区里管家里账的阿姨。中英文各九段话：平时四段，下雨一段，四季各一段。她说菜价、电费、孙子的学费，不碰吴阿姨楼里的事。行走图用人物生成器拼，深棕头发，上衣染成砖红色，跟吴阿姨的灰头发、紫红开衫分得开。
- 作品架上多了一个图标：一张米色、红色、绿色三块的饼图。
- 替身 Claude 的这一出交一本空账本：十二个月、全年、分类，共十四页、十三张图。分类有工资、退休金、买菜做饭、水电燃气这些，共十一个。
- 场景 `ledgerbook` 查这几样：
  - 账本在。用系统自带的解压工具拆开看：十四页、十三张图，一月有分类下拉单和按分类求和的公式，一行记录都没有。
  - 成品卡有缩略图，写着账本的文件名。
  - 账本在印刷铺做，做完柜台上就有那本账簿。
  - 回到主店，阿灯说印刷铺柜台上多了本账簿。秦阿姨进门说话。
- 中英文都过，截图看过。
- 又拿这台电脑上的 Excel 实打实开了一遍替身做的账本，中英文各一本。十四页都在，每月一张饼图，全年一张柱状图，分类那栏的下拉单取的是分类页。一月填五笔账，Excel 算出来收入 5000、支出 155.2、结余 4844.8，按分类和全年的数也都跟 `formula.ts` 算的一样。导出的饼图起先每个空分类旁边都标着 0%，挺乱，就把零的那一格去掉了。
- 留着没做：真 Key 一单约 $3，等 Lewis 说可以再跑。用户自己填过的账本，`edit_xlsx` 改不了：带图的工作簿它一向不改，会让店员把要改的地方写下来。

### H6 旅行手账

**现状：** 已经有“旅行攻略”（`travel`），出的是一篇攻略文档。路线图写的时候没注意到它。

**设计：** 先问 Lewis（Q-H1）。建议不另开一种，在旅行攻略上加一个“手账版”：一页 A4 竖排，路线、每天的清单和一张地图截图排在一起，能打印。递单时在旅行攻略里选。

**完成标准：** 按 Q-H1 定。照建议做的话：快照测试；场景 `journal`；真 Key 约 $3。

**做法：**

- Q-H1 照建议做，还是暂定：不另开一种，旅行攻略多一个“手账”版式。委托单上选了旅行攻略，贴纸下面多一行“版式：攻略 / 手账”，默认是攻略。换成别的贴纸，这一行就收起来；再选回旅行攻略，又从攻略开始。
- 版式记在委托单的 `layout` 里，模板表里写明哪种委托有哪些版式。现在只有旅行攻略有。别的委托就算带了 `layout`，提示词也不变。
- 手账版的提示词要一页 A4 竖排的页面。最上面是路线，下面每天一栏清单（去哪、做什么、带什么），再加一张路线小图。存成 PDF 以后用 Read 看一遍，确认只有一页，字也没有切掉。
- 地图截图改成了自己画。店里没有办法截网上的地图，页面也不能从网上加载东西，否则断网就印不出来。所以提示词要求用 SVG 画一张草图：地点是点，按行程的先后连起来，标上名字和第几天。
- 成品卡片打开手账的 PDF，不打开排版用的页面。
- 不加新客人，也不加新的长出来的东西，跟旅行攻略共用明信片。

### H2 小游戏

**现状：** 工坊做“小工具”（`tool`）和“小网页”（`page`），都是单页 HTML。

**设计：** 工坊出一个单文件的小游戏，浏览器里打开就能玩，不联网。规模限在一个下午能玩完的：翻牌、打地鼠、贪吃蛇这一类。复核时用 `render_png` 把游戏的第一屏画成图，老石看画面对不对。客人是想给孩子做个游戏的爸爸。长出来的东西是工坊墙上的一台小游戏机。

**完成标准：** 快照测试；场景 `minigame` 里用替身 Claude 出一个游戏，在浏览器里打开能动。真 Key 约 $4。

**做法：**

- Q-H2 照建议做，还是暂定：不用外面的库，一个文件，不联网。
- 新委托“做个小游戏”，工坊做。提示词要一个单页：标题、一句玩法、开始按钮、看得见的分数，一局完了能再来。鼠标、手指都能玩，要按键的游戏也能用键盘。给孩子玩的，块要大、节奏要慢，不吓人，也不用倒计时逼人。
- 写完用 `render_png` 把第一屏画成 800×600 的图，自己用 Read 看一遍，再把这张图交给老石复核。

### H9 工坊接活

**现状：** 没有。委托只在自己的文件夹或用户借来的文件夹里干活，不碰代码仓库的分支。

**设计：** 照路线图第 6 节：借一个代码仓库给工坊，修理工开自己的分支干活，不碰原来的分支、不推到网上。干活时工坊里看得到读了哪些文件、改到第几处、测试跑没跑。做完拿验货单来：改了哪些文件、每处为什么改、测试结果。批了，分支留着由用户自己合；不批，分支删掉（Q-F12）。

**完成标准：** 单元测试：只在新分支上写，原分支一个字节不动，不推送。场景 `repair`：用替身 Claude 改一个小仓库，批一次、不批一次。真 Key 约 $3：在一个练习仓库里修一个小错。
